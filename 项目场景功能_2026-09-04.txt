============================================================
一、项目场景总流程
============================================================

1. 游戏启动后进入 Main 主场景。
2. 玩家选择“新游戏”“读取存档”或“退出游戏”。
3. 新游戏或读取白天存档后进入 Clinic 诊室场景。
4. Clinic 进入时先检查当前场景、天数、前置剧情、名望和知识条件能够触发的剧情。
5. 没有自动剧情时生成 random 患者，玩家完成把脉、断病、开方并查看治疗结果。
6. Clinic 的白天时间从辰时推进到申时；现实60秒对应游戏内1个时辰。
7. 白天计时结束时，如果当前仍有患者，系统不立即切夜晚，而是把当前患者作为“最后一位病人”。
8. 最后一位病人完成诊疗并关闭判定结果后，Clinic 才发送 clinic_finished。
9. Main 在正常白天结束时统一结算当天银钱支出，切换为 Night，并保存。
10. Night 正常进入时优先显示“今日银钱结算”提示；玩家关闭结算后才检查 trigger_scene = night 的自动剧情。
11. Night 可阅读已经解锁的医书条目；存在可读未读条目时不能正常进入下一天。
12. 玩家点击“休息，进入明天”并通过未读检查后，Main 还会检查 trigger_type = night_end 的剧情。
13. 没有 night_end 剧情时，GameTime.finish_night() 令天数+1并回到 Clinic。
14. 普通剧情继续由 Story 场景表现；剧情内诊疗仍使用隐藏 Clinic 后端。
15. Story 支持普通结束、治疗成功、失败重试、失败返回、治疗失败 Game Over，以及“天数+名望”终局 Game Over。
16. Game Over 类型剧情不覆盖最后一个可读取存档点，结束后返回 Main 主菜单。
17. random 患者治疗除名望和心得外，已经接入诊费、药材销售和药材进货成本账本。
18. 顶部栏现在统一显示日期/时辰、名望及医术称号、心得和银钱。

当前主要可用场景：

1. Main：主菜单、存档槽、场景调度、剧情覆盖和自动存档。
2. Clinic：白天接诊、时间推进、诊疗、患者结算和当日结束。
3. PulseWindow：脉诊窗口。
4. PrescriptionWindow：断病、药材开方和预制方剂填入。
5. ClinicalLogWindow：行医记考窗口。
6. JudgementResult：处方判定结果窗口。
7. Night：夜晚主场景、银钱日结展示、读书和次日推进。
8. ReadBook：医书阅读窗口。
9. Story：剧情播放及剧情诊疗表现层。
10. PlayerHintWindow：通用提示和夜间银钱结算显示。
11. InfoWindow：Clinic 与 Night 共用的 Debug 开发测试窗口，不属于正式玩家流程。

Map 状态：

1. Main 中仍保留 Map 加载入口和 return_scene = map 的兼容逻辑。
2. 当前仓库仍没有 Scene/Map/Map.tscn。
3. 任何需要返回 map 的路径都必须继续视为“未完成地图功能”，不能视为正式可用场景。
4. 当前代码使用安全回退，避免缺少 Map 场景导致游戏崩溃。

============================================================
二、Main 主场景
============================================================

场景职责：

1. 作为整个游戏的常驻根场景。
2. 显示开始菜单。
3. 管理三个存档槽。
4. 创建、隐藏、清理和切换 Clinic、Night、Story 等子场景。
5. 接收白天结束、夜晚结束和剧情结束信号。
6. 在关键流程节点调用 SaveManager 保存。
7. 保证剧情播放时不直接销毁当前诊室或夜晚场景。
8. 在隐藏 Clinic 或 Night 前取得当前实际季节背景，并把贴图注入 Story。
9. 接收 Story 台词播放完成通知，按 StoryData 结算剧情名望与心得。
10. 正常白天结束时调用银钱日结。
11. 夜晚结束前检查 night_end 剧情。
12. 识别多种 Game Over 剧情并保证失败状态不覆盖最后可读存档。

主要界面：

1. 游戏标题区域。
2. “新游戏”按钮。
3. “读取存档”按钮。
4. “退出游戏”按钮。
5. 三槽存档选择弹窗。
6. 覆盖旧存档确认框。

新游戏流程：

1. 点击“新游戏”。
2. 打开三个存档槽。
3. 空槽显示新游戏槽位并允许选择。
4. 已有存档显示存档摘要和保存时间。
5. 选择已有存档时先弹出覆盖确认。
6. 取消覆盖后返回槽位选择。
7. 确认后设置当前槽位并重置本局状态。
8. 新档先安全写入；写入失败时保留旧存档并阻止进入游戏。
9. 写入成功后进入第1天 Clinic。
10. 新银钱状态也随新游戏初始化，当前起始银钱为0文。

读取存档流程：

1. 点击“读取存档”。
2. 三个槽位读取摘要。
3. 有存档的槽位可点击，空槽不可点击。
4. 读取成功后根据 GameTime 昼夜状态决定进入 Clinic 或 Night。
5. 读取失败时留在槽位界面。
6. UnlockManager 对旧账本保留兼容逻辑，旧存档未结算的当前日允许继续按旧口径处理，下一天切换为新版账本。

子场景挂载结构：

1. CurrentSceneRoot：放置当前 Clinic、Night 或未来 Map。
2. StorySceneRoot：放置正在播放的 Story 覆盖层。
3. StoryTreatmentBackendRoot：放置剧情诊疗所需的隐藏 Clinic 后端。

Clinic 进入处理：

1. 清理旧普通子场景。
2. 实例化 Clinic。
3. 连接 clinic_finished 和 story_requested。
4. 设置当前天数。
5. 调用 start_new_day()。
6. Clinic 先检查自动剧情；没有剧情才生成 random 患者。

Night 进入处理：

1. 清理旧普通子场景。
2. 实例化 Night。
3. 连接 night_finished 和 story_requested。
4. 调用 start_night(current_day, show_finance_report)。
5. 正常白天结束进入 Night 时 show_finance_report = true。
6. 剧情结束直接返回 Night 时可用 show_finance_report = false，避免重复显示日结。

正常白天结束流程：

1. Clinic 发出 clinic_finished。
2. Main 调用 Unlock.settle_day_finances(current_day)。
3. 银钱收入已在白天患者结算时实时入账；这里主要扣除当天药材进货成本和到期固定支出。
4. 调用 GameTime.finish_day()，把阶段切为 Night，不增加天数。
5. 保存。
6. 进入 Night。
7. Night 显示该日银钱结算报告。
8. 玩家关闭报告后，再进行夜晚 scene_enter 剧情检查。

剧情结束直接进入 Night 的特殊流程：

1. 如果剧情从白天 Clinic 触发并 return_scene = night，Main 只结束白天阶段。
2. 该路径不再次执行当天固定支出结算。
3. 该路径进入 Night 时不显示银钱日结。
4. 这样避免剧情切场景造成重复扣款或重复显示账单。

Night 结束处理：

1. Night 正常通过未读条目检查后发出 night_finished。
2. Main 先调用 StoryManager.find_night_end_story(current_day)。
3. 如果找到可触发 night_end 剧情，先播放剧情，不立即增加天数。
4. 没有 night_end 剧情时调用 GameTime.finish_night()。
5. 天数+1，阶段回到白天。
6. 保存并进入 Clinic。

剧情覆盖处理：

1. Clinic 或 Night 发送 story_requested。
2. Main 加载 StoryData 并检查 story_id、play_once 和播放记录。
3. 读取 StoryData.return_scene。
4. 从 Clinic 触发剧情时暂停诊室计时，保留当前进度。
5. 非 Game Over 剧情进入前保存一次。
6. Game Over 类型剧情进入前不覆盖最后可读存档。
7. 隐藏当前 Clinic/Night 前读取 get_current_background_texture()。
8. 把当前背景注入 Story。
9. Story 每段台词真正完成时发送 story_playback_completed。
10. Main 按 StoryData.reputation_points_change 和 experience_points_change 结算。
11. 非 Game Over 且成长变化时保存。
12. 剧情正式结束后才登记 story_id 和首次完成日。
13. 连续剧情切换前登记上一段已完整播放剧情。
14. 普通剧情结束后返回配置目标。
15. Game Over 清理本局临时状态并回到主菜单，不覆盖磁盘上的最后可读存档。

当前 Game Over 类型：

1. story_npc_failed_over：剧情诊疗失败终局。
2. day_reputation_over：达到指定绝对天数且当前名望大于等于门槛时触发终局。
3. day_reputation_below_over：达到指定绝对天数且当前名望严格低于门槛时触发终局。

Main 主要自动存档节点：

1. 新游戏创建成功。
2. 非 Game Over 剧情进入前。
3. 普通连续剧情切换。
4. 普通剧情结束。
5. 正常白天结束。
6. 正常夜晚结束。
7. random 患者第一次提交处方并产生账本变化后。
8. random 患者产生名望、心得或新条目解锁时。
9. 非 Game Over 剧情完整播放并产生名望或心得变化时。
10. Debug 测试窗口修改重要状态后。

============================================================
三、Clinic 白天诊室场景
============================================================

场景职责：

1. 显示当前日期、时辰、名望、医术称号、心得和银钱。
2. 按当前天数切换诊室季节背景。
3. 生成和显示 random 患者。
4. 提供把脉、开方和行医记考入口。
5. 调用方剂判定系统进行治疗评分。
6. 更新患者治疗前、治疗成功和治疗失败表现。
7. 为 random 患者结算名望、心得、知识解锁和银钱。
8. 在隐藏后端模式中为 Story 提供剧情NPC诊疗能力。
9. 诊室时间结束后完成“最后一位病人”逻辑，再通知 Main 进入 Night。
10. 对季节背景执行淡入淡出切换。

主界面可见内容：

1. 诊室背景。
2. 桌案前患者立绘。
3. 患者姓名。
4. 患者当前台词。
5. 顶部栏：日期/时辰、名望及称号、心得、银钱。
6. “把脉（F1）”入口。
7. “开方（F2）”入口。
8. “行医记考（F3）”入口。
9. 桌案图片上的把脉、开方、行医记考可点击热点区域。
10. Debug 构建中的 Ctrl+T InfoWindow。

桌案热点：

1. Clinic.tscn 在桌案图上增加把脉、开方、行医记考三个透明按钮热点。
2. 热点按原桌案图坐标定义多边形区域。
3. 窗口尺寸变化时，热点会按实际桌案图片缩放同步位置和大小。
4. 鼠标悬停/按下时有轮廓提示。
5. 点击热点最终转发到原有三个功能按钮，因此不会改变诊疗后端流程。
6. F1/F2/F3 快捷键仍然有效。

顶部栏名望称号：

1. 名望 <= 100：初窥门径。
2. 名望 101～300：略有小成。
3. 名望 301～600：融会贯通。
4. 名望 601～2000：炉火纯青。
5. 名望 > 2000：出神入化。
6. 名望显示格式为“名望：数值　称号”。

银钱显示：

1. 内部以“文”为统一记账单位。
2. 1两 = 1000文。
3. 金额为正时显示“两/文”的非零单位组合。
4. 金额为负时显示“欠 ……”。
5. 银钱在 random 患者结算和日结后即时刷新。

季节背景规则：

1. 24天为一轮。
2. 第1至第6天：春。
3. 第7至第12天：夏。
4. 第13至第18天：秋。
5. 第19至第24天：冬。
6. 第25天重新从春季开始。
7. 初次进入从黑色渐入。
8. 季节变化时执行“渐出到黑色—换图—渐入”。
9. 单次渐出/渐入默认约0.45秒。

当天开始流程：

1. Main 传入当前天数。
2. Clinic 更新季节背景和顶部栏。
3. 重置当天结束标记。
4. 重置“诊室时间已结束等待当前患者”状态。
5. 先查询 Clinic 场景可触发剧情。
6. 有剧情时交给 Main，不生成普通患者。
7. 没有剧情时生成 random 患者。

患者显示：

1. 显示患者姓名、立绘和台词。
2. random 患者从左侧偏移位置滑入并渐显。
3. 普通患者疾病从当前可用疾病池中分配。
4. story NPC 由 StoryData.clinic_npc_id 与 clinic_disease 指定，仅在隐藏后端准备。
5. 治疗成功使用治疗后表现。
6. 治疗失败保留失败表现和失败台词。
7. 治疗结果先通过患者台词反馈，再显示 JudgementResult。

患者切换：

1. random 患者完成判定并关闭结果后通常生成下一位患者。
2. 如果白天时间已经耗尽，关闭当前患者结果后不再生成新患者，而是结束白天。
3. story NPC 关闭结果后按 treatment_source_story_id 查找成功/失败后续剧情。
4. failed_retry 后清空上一轮处方，回到同一剧情NPC诊疗。
5. 没有失败后续剧情时仍可直接重试。

诊室时辰：

1. Clinic 进入后启动白天计时。
2. 顶部栏随 GameTime 刷新。
3. Story 覆盖期间暂停诊室计时。
4. 剧情返回 Clinic 后恢复原进度。
5. 白天从辰时开始，到申时结束。
6. 现实60秒对应1个游戏时辰。

“最后一位病人”规则：

1. 白天计时耗尽时先停止计时。
2. 如果当前没有有效患者，可以直接结束 Clinic。
3. 如果当前仍有患者，设置 clinic_time_expired_waiting_for_current_patient。
4. 提示玩家“今日接诊时间已结束，请完成当前病人的诊疗。完成后将自动进入夜晚。”
5. 此时不再允许切换或生成下一名 random 患者。
6. 当前患者仍可正常把脉、断病、开方、提交和查看结果。
7. 当前患者的 JudgementResult 关闭后自动发送 clinic_finished。
8. 该机制避免计时刚结束时直接中断一张尚未完成的处方。

============================================================
四、PulseWindow 脉诊窗口
============================================================

场景职责：

1. 显示当前患者的左右手脉象。
2. 根据疾病数据绘制脉象曲线。
3. 使用按键组合快速查看整只手的四宫格脉象。
4. 在其它按键状态下回到按键提示页。

窗口结构：

1. 按键提示页。
2. 右手脉象页。
3. 左手脉象页。

窗口行为：

1. 固定位置默认为 Vector2i(0, 36)。
2. 窗口显示时脚本会把位置锁回固定坐标，阻止拖动标题栏改变位置。
3. F1/F2/F3 可在诊疗窗口之间切换或置顶。
4. Esc 可关闭当前脉诊窗口。

脉位映射：

1. Q：右尺，对应肾阳。
2. A：右关，对应脾。
3. Z：右寸，对应肺。
4. W：左尺，对应肾阴。
5. S：左关，对应肝。
6. X：左寸，对应心。
7. 浮脉作为左右整手显示中的共同区域。

当前键盘查看规则：

1. Q+A+Z 三键同时按下，并且左手 W/S/X 均未按时，显示右手整手四宫格。
2. W+S+X 三键同时按下，并且右手 Q/A/Z 均未按时，显示左手整手四宫格。
3. 其它组合状态返回按键提示页。
4. 当前键盘流程不再按单个 Q/A/Z/W/S/X 就直接停留在单个脉象页。
5. 这样可以避免松键过程中闪过某一个单独脉象。

右手显示顺序：

1. 浮脉。
2. 右尺。
3. 右关。
4. 右寸。

左手显示顺序：

1. 浮脉。
2. 左尺。
3. 左关。
4. 左寸。

无效数据处理：

1. 没有有效患者或疾病时清空显示。
2. 未找到区域数据时只给出提示，不执行诊断判定。

============================================================
五、PrescriptionWindow 断病与开方窗口
============================================================

场景职责：

1. 让玩家选择判断出的疾病。
2. 搜索药材并填写剂量。
3. 按君、臣、佐、使四区组织处方。
4. 支持搜索已经解锁的预制方剂并一键填入。
5. 校验断病和处方。
6. 把提交请求交给 Clinic 的统一判定流程。

窗口行为：

1. 固定位置默认为 Vector2i(0, 36)。
2. 窗口显示时位置被锁定，不能拖离固定位置。
3. 打开窗口时优先聚焦疾病搜索框。
4. F1/F2/F3 可切换诊疗窗口。
5. 1/2/3/4 和小键盘1/2/3/4切换君、臣、佐、使。
6. 搜索框有内容时按 Esc 会先清空当前搜索并保持焦点。

断病区域：

1. 显示疾病搜索输入框。
2. 显示已经可用的疾病列表。
3. 支持疾病中文名搜索。
4. 支持疾病ID标准化完整拼音搜索。
5. 支持ID拼音首字母搜索。
6. 点击疾病后写入 current_prescription 的 disease_id 和 disease_name。
7. 清除选择时同步清空处方中的疾病信息。

开方区域：

1. 显示药材搜索框和药材网格。
2. 支持药材中文名、标准化完整拼音ID和ID首字母搜索。
3. 显示君、臣、佐、使四个处方区。
4. 当前区域高亮。
5. 单位选项包括：分、钱、两、斤。
6. 默认单位为“钱”。
7. 左键点击药材时增加1个当前单位。
8. 同味药再次点击时通过底层统一“分”换算后累加。
9. 右键药材时按当前单位减少。
10. 剂量减至0或以下时移除该药材。
11. 四区中的已有药材可右键直接移除。
12. “清空处方”清空当前全部药材，但诊断信息由对应流程单独管理。
13. “提交处方”把处方送往 Clinic/Story 判定。

焦点顺序：

1. DiseaseSearch。
2. 君区。
3. 臣区。
4. 佐区。
5. 使区。
6. HerbSearch。
7. 再回 DiseaseSearch。
8. Shift+Tab 反向移动。

预制方剂功能：

1. 功能解锁条目ID为 yu_zhi_fang_ji。
2. 只有 yu_zhi_fang_ji 已解锁时才允许出现预制方剂搜索结果。
3. 还必须保证被搜索到的具体方剂对应医书条目已经解锁。
4. 药材搜索框为空时不主动列出全部预制方剂，避免打开窗口时塞满方剂按钮。
5. 输入方剂中文名、完整拼音ID或拼音首字母时，可匹配方剂。
6. 方剂按钮显示为“【方剂】方剂名”，与普通药材按钮区分。
7. 点击方剂按钮后先完整校验所有药材资源、剂量和单位。
8. 任意药材缺失或剂量无效时，不破坏玩家当前已经填写的处方。
9. 全部校验通过后清空四区药材，但保留玩家当前断病选择。
10. 再按方剂数据中的君、臣、佐、使和原始剂量完整填入。
11. 填入后提示“已按预制方剂填入：方剂名”。

提交前校验：

1. 没有选择疾病时显示“请先填入疾病。”
2. 没有药材时显示“请先填入药材。”
3. Clinic 后端仍会校验当前患者、患者真实疾病和标准方等必要条件。
4. 校验失败时通过 PlayerHintWindow 或 info_requested 显示原因。
5. 校验失败不进入判定窗口。

============================================================
六、处方判定、治疗结算与银钱
============================================================

判定输入：

1. 患者真实疾病。
2. 疾病对应标准方。
3. 玩家选择的疾病。
4. 玩家提交的君、臣、佐、使药材和剂量。

当前评级：

1. 100分：妙手回春。
2. 60至99分：治疗成功。
3. 0至59分：治疗失败。

random 患者名望和心得：

1. 妙手回春：名望+10，心得+1。
2. 治疗成功：名望、心得不变。
3. 治疗失败：名望-10，心得不增加。
4. 同一患者重复提交不重复结算名望。
5. 同一患者重复达到妙手回春不重复获得心得。
6. 心得增加后立即检查累计心得自动解锁。
7. 新条目解锁后刷新相关界面并保存。

银钱基础：

1. 内部统一单位：文。
2. 1两 = 1000文。
3. 新游戏起始银钱：0文。
4. 银钱允许为负数。
5. 负数显示为“欠 X两 Y文”或相应省略零单位的形式。

random 患者诊费：

1. 以“本次第一次提交处方这一刻”的当前名望决定。
2. 名望 <=100：10文。
3. 名望 101～300：50文。
4. 名望 301～600：200文。
5. 名望 601～2000：500文。
6. 名望 >2000：1000文。
7. 本次治疗随后产生的名望变化只影响下一位患者的诊费。

药材价格：

1. HerbData 增加 purchase_price、sell_price、price_unit。
2. purchase_price 表示进货价。
3. sell_price 表示售价。
4. price_unit 表示价格对应的剂量单位。
5. 当前默认 price_unit 为 qian。
6. 处方实际剂量和价格单位都经 HerbUnit 统一换算成“分”计算。
7. 最终银钱按文取整。

当前新版账本口径：

1. daily_consultation_income_wen：当天诊费收入。
2. daily_medicine_sales_wen：当天成功治疗产生的药材销售额。
3. daily_medicine_purchase_cost_wen：当天全部首次提交处方产生的药材进货成本。
4. 账本版本号2表示“销售额/进货成本分开记录”。
5. 旧账本字段仍保留用于旧存档当前未结算日兼容。

random 患者第一次提交处方的银钱流程：

1. 计算当前处方总进货成本。
2. 计算当前处方总售价。
3. 读取提交瞬间名望计算诊费。
4. 妙手回春/治疗成功：药材销售收入 = 当前处方售价总和。
5. 治疗失败：药材销售收入 = 0。
6. 无论成功或失败，本张处方的进货成本都进入当天支出。
7. 白天实时入账：诊费 + 成功时的药材销售额。
8. 药材进货成本不在患者判定瞬间扣除，而是在正常白天结束时统一扣除。
9. 同一名患者只有第一次提交允许产生银钱变化。
10. 每位 random 患者第一次提交后保存一次账本，避免中途退出丢失收入。

固定支出：

1. 陈皮工钱：500文，每2个节气支付一次。
2. 半夏工钱：500文，每2个节气支付一次。
3. 食费：2000文，每2个节气支付一次。
4. 第2、4、6……天/节气执行上述到期固定支出。
5. 未到支付日时对应项目为0，不显示也不扣除。

正常白天日结：

1. Main 正常收到 clinic_finished 时调用 settle_day_finances。
2. 同一天已经结算过时返回原报告，不重复扣款。
3. 总收入 = 诊费 + 药材销售额。
4. 总支出 = 药材进货成本 + 当日应付陈皮工钱 + 半夏工钱 + 食费。
5. 本日变化 = 总收入 - 总支出。
6. 银钱在日结时扣除支出。
7. 结算报告保存为 last_finance_report。
8. Night 正常进入后显示该报告。

旧存档账本兼容：

1. 老账本无法从“药材利润”反推出此前每张处方的销售额和成本。
2. 对旧存档当前尚未结算的一天保留版本1口径。
3. 下一天重置账本后自动切换为版本2新口径。
4. 这样避免强行拆分旧账造成金额错误。

story NPC：

1. story NPC 不使用 random 患者固定名望/心得奖惩。
2. story NPC 当前也不走 random 患者诊费和药材销售账本。
3. 治疗结果先决定成功/失败后续剧情。
4. 后续剧情完整播放后再按 StoryData 的 reputation_points_change 和 experience_points_change 结算。
5. Game Over 剧情不覆盖最后可读磁盘存档。

九、Night 夜晚场景
============================================================

场景职责：

1. 显示当天夜晚状态。
2. 显示银钱日结。
3. 提供读书入口。
4. 检查可读未读条目。
5. 满足条件后请求进入下一天。
6. 进入时检查夜晚 scene_enter 剧情。
7. 配合 Main 支持 night_end 剧情。
8. 根据当前节气显示四季夜景。
9. Debug 构建中提供 InfoWindow。

主界面：

1. 夜晚背景。
2. 顶部栏：日期、夜晚、名望及称号、心得、银钱。
3. “读书”按钮。
4. “休息，进入明天”按钮。
5. PlayerHintWindow。
6. Debug InfoWindow。

季节背景：

1. 第1至6天春夜。
2. 第7至12天夏夜。
3. 第13至18天秋夜。
4. 第19至24天冬夜。
5. 第25天重新春夜。
6. 初次进入从黑色渐入。
7. 季节变化执行渐出—换图—渐入。
8. Night 向 Main 提供当前实际背景贴图，供 current_scene 剧情使用。

正常进入 Night：

1. Main 已在正常 Clinic 结束时完成当日银钱结算。
2. Night 更新背景和顶部栏。
3. Night 再调用 settle_day_finances(day) 作为幂等兜底，防止特殊路径漏结算。
4. 读取 build_finance_report_text(day)。
5. 如果有结算报告，用 PlayerHintWindow 显示“今日银钱结算”。
6. 玩家关闭结算窗口后，等待下一帧再启动夜晚剧情检查。
7. 这样即使剧情资源较多，玩家也会先看到结算窗口立即消失。
8. 结算窗口关闭后检查 trigger_scene = night 的进入剧情。

剧情直接返回 Night：

1. Main 可调用 start_night(day, false)。
2. 此时不再显示银钱日结。
3. 直接进入夜晚剧情检查和夜晚主界面。
4. 用于避免剧情跳转重复日结。

进入明天规则：

1. 点击“休息，进入明天”时刷新当前心得和依赖解锁。
2. 检查药材、方剂、疾病、医理四类是否存在已解锁但未读的可读条目。
3. 有未读条目时显示“尚有未读条目，请先阅读后再休息”。
4. 没有未读条目时发送 night_finished。
5. Main 收到后先检查 night_end 剧情。
6. 有 night_end 剧情时先播放剧情。
7. 没有时 finish_night()，天数+1并进入 Clinic。

Debug：

1. Ctrl+T 只在 Debug 构建且 Night 可见时打开 InfoWindow。
2. Night 中测试“结束当天”可以直接发送 night_finished，用于跨天测试。
3. Night 没有当前病人，患者测试操作不可用。
4. Debug 修改数据后立即保存并刷新宿主界面。

十一、Story 剧情场景与 StoryManager
============================================================

Story 场景职责：

1. 播放 StoryData 对话和字幕。
2. 处理 default/current_scene 开场背景。
3. 根据 StoryLine 切换背景和人物立绘。
4. 支持打字机效果和剧情跳过。
5. 在剧情要求诊疗时打开把脉、开方、行医记考。
6. 发送台词播放完成、剧情结束、后续剧情、诊疗请求和 Game Over 请求。
7. 剧情台词完整播放后触发 StoryData 配置的名望和心得结算。

StoryManager 当前结构：

1. project.godot 当前 Autoload 名称仍为 StoryManager。
2. 实际加载脚本改为 System/Story/StoryManagerCached.gd。
3. StoryManagerCached 继承原 StoryManager.gd，不改变原剧情业务规则。
4. 首次扫描 res://Data/Story 后把 StoryData 强引用缓存到 Dictionary。
5. 后续 find_trigger_story、find_night_end_story、名望解锁等检查复用缓存。
6. 不再每次同步 load() 全部剧情 .tres。
7. 剧情路径仍由原 StoryManager 递归扫描 Data/Story 得到。
8. 路径排序仍决定同条件多剧情时的稳定检查顺序。
9. 缓存同时维护 path -> StoryData 和 story_id -> path。

画面结构：

1. 全屏剧情背景。
2. 半透明遮罩。
3. 左、中、右三个角色立绘位。
4. 对话框：角色名、正文、继续提示。
5. 字幕模式：居中字幕。
6. 剧情诊疗按钮区。
7. 脉诊、处方、行医记考和结果窗口。

背景：

1. background_mode = default：使用 Story 默认背景。
2. background_mode = current_scene：使用 Main 注入的当前 Clinic/Night 实际背景。
3. 第一行已指定背景时直接以第一行背景开场。
4. 单句 background 非空时覆盖当前背景。
5. 背景切换执行渐出到黑色—换图—渐入。
6. 过渡期间暂停台词推进。
7. 剧情结束前先渐出到黑色再发结束信号。

台词：

1. 对话行显示说话人和正文。
2. 字幕行使用居中字幕。
3. 当前说话人正常显示，其它人物支持 normal/dim/hide。
4. 立绘支持 left/mid/right/auto。
5. 同一 speaker 复用既有映射。
6. 使用完整文本 + visible_characters 实现打字机，降低容器抖动。
7. 文本未显示完时点击/空格先补全本句。
8. 本句完整时点击/空格进入下一句。
9. 长按回车约1秒可跳过剧情。
10. 每次 play_story 只上报一次 story_playback_completed。

当前触发类型：

1. scene_enter。
2. night_end。
3. day_reputation_over。
4. day_reputation_below_over。
5. story_npc_cured。
6. story_npc_failed_retry。
7. story_npc_failed_back。
8. story_npc_failed_over。

scene_enter：

1. 进入 Clinic/Night/未来 Map 时检查。
2. 如果 trigger_story_id 为空，trigger_day 按绝对游戏天数。
3. 如果 trigger_story_id 非空，必须先完成该前置剧情。
4. trigger_day 改为“前置剧情首次完成日 + N天”的相对判断。
5. play_once = true 且已播放时不再触发。

night_end：

1. Night 点击“休息，进入明天”并通过未读检查后，由 Main 检查。
2. trigger_scene 固定对应 night 语义。
3. 可使用 trigger_story_id 和相对 trigger_day。
4. 命中后先播放剧情，不立即增加天数。
5. 剧情结束后的去向由 return_scene 决定。

day_reputation_over：

1. 属于“绝对天数 + 当前名望”终局剧情。
2. trigger_day 必须大于0。
3. required_reputation_points 必须大于0。
4. trigger_story_id 必须为空。
5. 当前名望大于等于门槛时满足。
6. 在进入指定场景时检查。
7. 结束后直接回 Main 主菜单。
8. 不覆盖最后一个可读存档。

day_reputation_below_over：

1. 同样使用绝对天数。
2. trigger_day 必须大于0。
3. required_reputation_points 必须大于0。
4. trigger_story_id 必须为空。
5. 当前名望严格小于门槛时满足。
6. 结束后回 Main 主菜单。
7. 不覆盖最后一个可读存档。

进入场景剧情检查优先级：

1. 先 day_reputation_over。
2. 再 day_reputation_below_over。
3. 最后普通 scene_enter。
4. 这样满足终局条件时不会先播放普通自动剧情。

治疗结果剧情：

1. story_npc_cured：治疗成功。
2. story_npc_failed_retry：失败剧情后回到同一诊疗。
3. story_npc_failed_back：失败后按 return_scene 返回。
4. story_npc_failed_over：失败 Game Over。
5. 治疗结果剧情必须填写 trigger_story_id。
6. trigger_story_id 必须等于发起这次治疗的主剧情。
7. trigger_day 必须为0。
8. 治疗结果立即匹配，不支持延迟若干天。

名望条件：

1. 普通剧情 required_reputation_points > 0 时，仍由 UnlockManager 的剧情解锁记录控制。
2. day_reputation_over/below_over 不依赖历史解锁记录，而是直接读取触发当下的实际名望。
3. 名望增加后 UnlockManager 会扫描 StoryManager.get_all_stories() 刷新可解锁剧情。

unlock_entry_id：

1. 当前实际运行逻辑把 unlock_entry_id 作为“剧情触发前置医书条目”。
2. 字段为空时不限制。
3. 字段非空时必须先由其它系统解锁对应条目。
4. StoryManager 只检查，不自动赠送。
5. UnlockManager 也不会因为剧情名望解锁而自动解锁该条目。
6. 当前 StoryData.gd 中仍存在一处偏旧的字段注释，但 StoryManager/UnlockManager 的实际代码已经统一按“前置条件”执行。

一次性剧情：

1. 使用稳定 story_id。
2. 剧情开始时不立即登记为已播放。
3. 台词完整播放后先结算成长。
4. 正式结束或连续剧情切换时再登记播放状态。
5. played_story_ids 记录已完成。
6. played_story_days 记录首次完成日。
7. play_once = false 的剧情也记录首次完成日，可供其它剧情做前置。
8. 旧存档缺少 played_story_days 时按第0天兼容。

剧情内诊疗：

1. StoryData 配置 clinic_npc_id 后，在台词结束时请求诊疗。
2. clinic_disease 决定本次剧情诊疗疾病。
3. 同一 story NPC 可在不同剧情中使用不同疾病。
4. Main 在 StoryTreatmentBackendRoot 创建隐藏 Clinic。
5. Story 继续显示在最上层。
6. 三个诊疗窗口与普通 Clinic 共用规则。
7. 关闭 JudgementResult 后按 treatment_source_story_id 匹配成功/失败剧情。
8. failed_retry 或无失败剧情兜底会重置处方并允许重试。

十四、银钱、名望、心得与解锁
============================================================

心得：

1. 作为累计值，不再作为读书消耗货币。
2. 正数增加时检查达到门槛的新条目。
3. 负数最低保持0。
4. 已解锁条目不会因心得降低而重新锁回。

名望：

1. 作为累计值，可正可负。
2. random 患者治疗评级影响名望。
3. StoryData 可配置剧情名望变化。
4. 名望决定顶部栏医术称号。
5. 名望决定 random 患者诊费档位。
6. 名望还参与普通剧情解锁和终局条件。

银钱：

1. 新增为正式持久状态。
2. random 患者诊费和成功治疗药材销售在白天实时入账。
3. 药材进货成本和固定支出在正常白天结束时统一扣除。
4. Night 负责向玩家展示当天结算报告。
5. 同一天日结幂等，防止重复扣款。
6. 旧存档保留旧账本当前日兼容。
7. 银钱允许负数，没有在当前代码中发现“银钱为负立即 Game Over”的直接规则。

实体解锁：

1. 药材条目解锁后可读，第一次阅读同步解锁药材。
2. 方剂：所需药材依赖满足后自动解锁方剂和条目。
3. 疾病：推荐标准方解锁后自动解锁疾病和条目。
4. 医理按累计心得门槛解锁。
5. clinical_log 只显示同步解锁实体。

新增预制方剂依赖：

1. yu_zhi_fang_ji 解锁后开启 PrescriptionWindow 的方剂搜索/一键填入能力。
2. 具体方剂条目也必须已解锁。
3. 这使“知道如何使用预制方剂”和“已经掌握这张具体方剂”成为两个独立条件。

十六、场景间信号和结果对应关系

   接收方：Main

   接收方：Main

4. Night.story_requested
   发送方：Night
   接收方：Main
   结果：播放夜晚 scene_enter 剧情。

5. Story.story_playback_completed
   发送方：Story
   接收方：Main
   结果：结算 StoryData 名望/心得；非 Game Over 有变化时保存。

6. Story.story_finished
   发送方：Story
   接收方：Main
   结果：登记已播放、保存并返回目标场景。

7. Story.story_treatment_requested
   发送方：Story
   接收方：Main
   结果：创建隐藏 Clinic 诊疗后端。

   发送方：Story
   接收方：Main
   结果：登记上一段剧情并切后续 StoryData；失败重试时保留诊疗上下文。

   发送方：Story
   接收方：Main
   结果：不保存失败后的状态，返回主菜单。

    发送方：PrescriptionWindow
    接收方：Clinic 或 Story

    发送方：JudgementResult
    接收方：Clinic 或 Story

    发送方：ReadBook
    接收方：Night

    发送方：PlayerHintWindow
