============================================================
1. 一句话说明
============================================================
《医者》是一个 Godot 4.6 制作的中医诊疗模拟游戏。玩家白天在诊室接诊，通过症状、脉象、病机判断疾病，并开出中药方剂；系统根据标准方剂评分，并根据治疗结果反馈 NPC 状态、评级图片、心得与名望收益。夜晚玩家读医书，消耗或积累阅读进度，逐步解锁药材、疾病、方剂、理论与行医记考内容，推动后续诊疗能力成长。

核心循环：
主菜单 → 新游戏 / 读档 → 白天诊室接诊 → 查看脉象 / 行医记考 → 开处方 → 评分结算 → 治疗反馈 / 名望与心得更新 → 夜晚读书 → 解锁知识 → 次日继续接诊 / 触发剧情

当前阶段判断：核心玩法 Alpha 中期。主框架、数据系统、接诊流程、脉象显示、处方窗口、方剂评分、结算评级、夜读解锁、行医记考、三槽存档、时间推进、剧情系统、NPC 治疗前后台词均已存在。后续重点应放在 UI 动效、NPC 进出场表现、剧情内容扩充、病例/NPC 丰富度、工程目录整理与数据导入流程稳定化。

5. 主流程逻辑
============================================================
主入口：
- Scene/Main/Main.tscn
- Scene/Main/Main.gd

Main.gd 主要职责：
- 显示主菜单。
- 新游戏选择存档槽。
- 读档选择存档槽。
- 覆盖旧存档确认。
- 退出游戏。
- 在 Clinic / Night / Story 场景之间切换。
- 白天与黑夜结束时自动存档。
- 接收 Clinic 的剧情请求，并在剧情结束后返回原流程。

当前主场景预加载：
- res://Scene/Clinic/Clinic.tscn
- res://Scene/Night/Night.tscn
- res://Scene/Story/Story.tscn

流程：
1. 新游戏：选择槽位，必要时确认覆盖，重置时间、解锁、剧情记录并创建存档。
2. 白天：进入 Clinic 接诊。
3. 接诊中可查看脉象、行医记考、打开处方窗口。
4. 提交处方后进行评分，显示 JudgementResult。
5. 根据评分更新 NPC 治疗状态、心得、名望、可触发剧情。
6. 当天结束后进入 Night。
7. 夜晚读书，阅读 / 解锁条目。
8. 未读条目检查通过后休息，进入下一天。
9. StoryManager 可在 Clinic 或 Night 阶段触发剧情。

6. 诊室系统
============================================================
相关文件：
- Scene/Clinic/Clinic.tscn
- Scene/Clinic/Clinic.gd
- Scene/Clinic/JudgeResult.gd
- Scene/JudgementResult/JudgementResult.tscn
- Scene/JudgementResult/JudgementResult.gd

Clinic.gd 是当前白天玩法主控制脚本，职责较多：
- 管理当前病人 / NPC。
- 显示患者姓名、立绘、台词、症状与诊疗信息。
- 接入 GameTimeManager，显示日期与时辰。
- 显示心得与名望。
- 打开 / 关闭脉象窗口。
- 打开 / 关闭处方窗口。
- 打开 / 关闭行医记考窗口。
- 提交处方并调用 FormulaJudge 评分。
- 打开 JudgementResult 结算窗口。
- 根据评分决定治疗成功、失败或妙手回春。
- 成功时切换治疗后立绘和治疗后台词。
- 失败时保留治疗前立绘并显示治疗失败台词。
- 支持下一名 / 上一名 / 生成随机 NPC。
- 支持开发测试入口。
- 支持从 Clinic 请求剧情播放。

JudgeResult.gd：
- class_name JudgeResult
- extends RefCounted
- 用于承载判方结果。
- 当前仍放在 Scene/Clinic/ 下，但它实际属于处方评分逻辑，未来更适合移动到 System/Formula/ 或 System/Prescription/。

JudgementResult.gd：
- extends Control。
- 显示病人疾病、标准方、玩家断病、玩家处方、新解锁条目。
- 根据 grade 显示评级图片。
- 当前评级规则：
  - 100 分：妙手回春
  - 60~99 分：治疗成功
  - 0~59 分：治疗失败

当前待做：
- NPC 进入 / 离开 Clinic 场景时还没有检测到已实现淡入淡出逻辑；可在 Clinic.gd 的刷新病人、结算后切换下一名病人处加入 Tween 控制 portrait_rect 和台词框 alpha。
- Clinic.gd 职责已经很重，后续可拆分为 PatientView、ClinicFlowController、ClinicWindowController、TreatmentResultHandler。

8. 处方与方剂评分系统
============================================================
相关文件：
- Scene/Prescription/Prescription.gd
- Scene/Prescription/PrescriptionWindow.tscn
- Scene/Prescription/PrescriptionWindow.gd
- System/Formula/FormulaJudge.gd
- System/Formula/FormulaData.gd
- System/Formula/FormulaIngredient.gd
- System/Formula/FormulaDataBase.gd
- System/Herb/HerbUnit.gd

Prescription.gd：
- class_name Prescription
- extends RefCounted
- 表示玩家开的处方。
- 当前放在 Scene/Prescription/ 下，但它是纯数据逻辑，不是 UI，后续可移动到 System/Formula/ 或 System/Prescription/。

PrescriptionWindow.gd：
- class_name PrescriptionWindow
- extends Window
- 处方窗口 UI 控制。
- 负责选择疾病、选择药材、设置剂量、设置君臣佐使、提交处方。
- 已接入 PlayerHintWindow，用于提示“请先填入疾病”“请先填入药材”等操作错误。
- 药材与疾病选择会受到 UnlockManager 解锁状态影响。
- 可从处方窗口跳转打开行医记考。

FormulaJudge.gd：
- class_name FormulaJudge
- extends RefCounted
- 负责将玩家处方与标准方剂比较。
- 当前评分规则为区域判定版：
  - 基础分 100。
  - 疾病判断错误或未选择，扣 100。
  - 君药区错误扣 40。
  - 臣药区错误扣 30。
  - 佐药区错误扣 20。
  - 使药区错误扣 10。
  - 区域错误包括缺药、多药、放错区域、剂量不一致。
  - 最终分数 max(0, 100 - 总扣分)。
  - 100：妙手回春；60~99：治疗成功；0~59：治疗失败。

HerbUnit.gd：
- 处理中药剂量单位。
- 当前涉及分、钱、两、斤等单位换算。

Night.gd：
- class_name 未注册，extends Control。
- 控制夜晚主场景。
- 显示日期、时辰、心得、名望。
- 打开 ReadBook 窗口。
- 休息前检查是否还有未读的疾病 / 方剂类解锁条目。

ReadBook.gd：
- class_name ReadBook。
- 控制读书窗口。
- 显示医书列表、条目列表、条目内容。
- 调用 Unlock.refresh_auto_unlocks_by_experience() 刷新自动解锁。
- 显示累计心得。
- 阅读条目后更新阅读状态、心得与可读条目。

UnlockManager.gd：
- class_name UnlockManager
- extends Node
- 作为 Autoload：Unlock。
- 管理已解锁条目、已阅读条目、药材 / 疾病 / 方剂解锁、行医记考解锁内容、读书天数、累计心得、名望、已解锁剧情。
- 条目自动解锁主要依赖 BookEntryData.unlock_required_experience_points。
- 行医记考会同步记录已解锁的药材、疾病、方剂实体。
- 名望达到 StoryData.required_reputation_points 后可解锁剧情，但 StoryData.unlock_entry_id 当前作为剧情触发前置条目，不再由 UnlockManager 自动解锁。

Book 系统：
- BookData.gd / BookDataBase.gd：医书本体数据和数据库。
- ClinicalLogData.gd：行医记考类 BookData。
- HerbBookData / DiseaseBookData / FormulaBookData / TheoryBookData：不同书籍类型。
- BookEntryData.gd / BookEntryDataBase.gd：医书条目数据和数据库。
- HerbBookEntryData / DiseaseBookEntryData / FormulaBookEntryData / TheoryBookEntryData：不同类型条目数据。

- 不要随意修改 Autoload 名称：FormulaDB、DiseaseDB、BookEntryDB、BookDB、HerbDB、Unlock、GameTime、SaveManager、StoryManager。

- 修改读书逻辑时，要同时考虑：UnlockManager 的 entry 解锁、read 状态、experience_points、clinical_log 同步。
- 修改评分逻辑时，要同时考虑：FormulaJudge、JudgeResult、JudgementResult、Clinic.submit_prescription、NPC 治疗状态与名望奖励。
