《医者》项目场景功能详细大纲

整理日期：2026-08-05
项目：Doctor / 医者
引擎：Godot 4.6
文档范围：基于当前 main 分支已经存在的场景、脚本与数据流程进行整理。
说明：本文件只细化当前项目功能，不增加新的剧情分支，不创建或修改 GitHub 分支。

============================================================
一、项目场景总流程
============================================================

1. 游戏启动后进入 Main 主场景。
2. 玩家选择“新游戏”“读取存档”或“退出游戏”。
3. 新游戏或读取白天存档后进入 Clinic 诊室场景。
4. 白天在诊室接诊、把脉、断病、开方并查看治疗结果。
5. 白天结束后进入 Night 夜晚场景。
6. 夜晚阅读已经解锁的医书条目。
7. 当晚所有可读新条目都已查看后，玩家可以进入下一天。
8. Clinic 或 Night 到达剧情触发条件时，由 Main 在当前场景上方播放 Story 剧情覆盖层。
9. 剧情结束后，根据剧情数据返回诊室或夜晚；Game Over 剧情返回主菜单。
10. 白天结束、夜晚结束、剧情切换和重要成长变化时写入当前存档槽。

当前主要可用场景：

1. Main：主菜单、存档槽、场景调度和自动存档。
2. Clinic：白天接诊和诊疗主场景。
3. PulseWindow：脉诊窗口。
4. PrescriptionWindow：断病与开方窗口。
5. ClinicalLogWindow：行医记考窗口。
6. JudgementResult：处方判定结果窗口。
7. Night：夜晚主场景。
8. ReadBook：医书阅读窗口。
9. Story：剧情播放及剧情诊疗场景。
10. PlayerHintWindow：通用提示窗口。
11. InfoWindow：诊室开发测试窗口，不属于正式玩家流程。

Map 只在 Main 中保留了加载入口，当前仓库没有 Scene/Map/Map.tscn。剧情返回目标如果填写 map，系统会警告并退回 Clinic，不能视为已经完成的地图场景。

============================================================
二、Main 主场景
============================================================

场景职责：

1. 作为整个游戏的常驻根场景。
2. 显示开始菜单。
3. 管理三个存档槽。
4. 创建、隐藏、清理和切换 Clinic、Night、Story 等子场景。
5. 接收白天结束、夜晚结束和剧情结束信号。
6. 在关键流程节点调用 SaveManager 保存。
7. 保证剧情播放时不直接销毁当前诊室或夜晚场景。

主要界面：

1. 游戏标题区域。
2. “新游戏”按钮。
3. “读取存档”按钮。
4. “退出游戏”按钮。
5. 三槽存档选择弹窗。
6. 覆盖旧存档确认框。

新游戏流程：

1. 点击“新游戏”。
2. 打开三个存档槽。
3. 空槽显示“新游戏槽位N／空存档”，允许直接选择。
4. 已有存档的槽位显示存档名称和保存时间。
5. 选择已有存档时弹出覆盖确认。
6. 取消覆盖后返回槽位选择。
7. 确认后设置当前槽位，重置游戏时间、知识解锁进度和剧情播放记录。
8. 先尝试安全写入新档；写入失败时保留原存档，不进入游戏。
9. 写入成功后隐藏主菜单，进入第1天 Clinic。

读取存档流程：

1. 点击“读取存档”。
2. 三个槽位读取存档摘要。
3. 有存档的槽位显示游戏进度名称和保存时间，并允许点击。
4. 空槽显示“空存档”，按钮不可点击。
5. 读取成功后根据 GameTime 中的昼夜状态决定场景：白天进入 Clinic，夜晚进入 Night。
6. 读取失败时留在槽位界面，不进入子场景。

退出游戏流程：

1. 点击“退出游戏”。
2. 直接调用 Godot 退出游戏。
3. 当前代码不会在退出按钮被点击时额外强制保存，因此玩家状态依赖之前的自动存档节点。

子场景挂载结构：

1. CurrentSceneRoot：放置当前 Clinic、Night 或 Map 实例。
2. StorySceneRoot：放置正在播放的 Story 覆盖层。
3. StoryTreatmentBackendRoot：放置剧情诊疗所需的隐藏 Clinic 后端。

Clinic 进入处理：

1. 清理旧的普通子场景。
2. 实例化 Clinic。
3. 先连接 clinic_finished 和 story_requested 信号。
4. 设置当前天数。
5. 调用 start_new_day()，开始当天自动剧情检查或生成日常患者。

Night 进入处理：

1. 清理旧的普通子场景。
2. 实例化 Night。
3. 先连接 night_finished 和 story_requested 信号。
4. 调用 start_night()，刷新夜晚状态并检查夜晚自动剧情。

剧情覆盖处理：

1. Clinic 或 Night 发送 story_requested。
2. Main 加载 StoryData，并检查 story_id、play_once 和是否已经播放。
3. 读取 StoryData.return_scene 作为剧情结束后的返回目标。
4. 从诊室触发剧情时暂停诊室计时，但保留已经经过的时辰进度。
5. 在进入剧情前保存一次当前状态。
6. 隐藏当前 Clinic 或 Night 画面，不立即销毁。
7. 在 StorySceneRoot 中创建 Story 场景。
8. 剧情真正结束后才把当前 story_id 记为已播放。
9. 连续剧情切换前，先把上一段完整播放的剧情记为已播放。
10. 普通剧情结束后保存，再回到配置的目标场景。
11. 返回 night 时先结束白天，再保存完整的夜晚状态，最后进入 Night。
12. Game Over 剧情结束后不覆盖磁盘存档，清理本局临时状态并回到主菜单。

Main 的主要自动存档节点：

1. 新游戏创建成功时。
2. 进入剧情前。
3. 切换到普通后续剧情时。
4. 普通剧情真正结束时。
5. 白天 Clinic 结束时。
6. 夜晚 Night 结束时。
7. 诊疗获得名望、心得或解锁内容时，由相应场景即时保存。

============================================================
三、Clinic 白天诊室场景
============================================================

场景职责：

1. 显示当前日期、时辰、名望和心得。
2. 按当前天数切换诊室季节背景。
3. 生成和显示患者。
4. 提供把脉、断病、开方和行医记考入口。
5. 调用方剂判定系统进行治疗评分。
6. 更新患者治疗前、治疗成功或治疗失败状态。
7. 发放名望、心得和新条目解锁。
8. 控制下一名患者和剧情患者的后续流程。
9. 诊室时间结束后通知 Main 进入夜晚。

主界面可见内容：

1. 诊室背景图。
2. 桌案前的患者立绘。
3. 患者姓名。
4. 患者当前台词。
5. 顶部栏：当前天数、当前时辰、名望、心得。
6. “把脉（F1）”按钮。
7. “开方（F2）”按钮。
8. “行医记考（F3）”按钮。

季节背景规则：

1. 每一天对应一个节气位置。
2. 24天为一轮。
3. 第1至第6天使用春季诊室背景。
4. 第7至第12天使用夏季诊室背景。
5. 第13至第18天使用秋季诊室背景。
6. 第19至第24天使用冬季诊室背景。
7. 第25天重新从春季开始循环。

当天开始流程：

1. Main 传入当前天数。
2. Clinic 更新季节背景。
3. 重置“当天已经结束”的防重复标记。
4. 刷新时辰、名望和心得显示。
5. 先查询 trigger_scene = clinic 且满足当前条件的自动剧情。
6. 如果触发剧情，先把请求交给 Main，不生成普通患者。
7. 没有自动剧情和指定剧情患者时，生成一名 random 类型患者。

患者显示功能：

1. 显示患者姓名、立绘和台词。
2. random 患者进入时播放缩放式入场动画。
3. 普通患者的疾病从当前已经解锁的疾病池中分配。
4. story 患者按剧情指定的 npc_id 和疾病数据生成。
5. 患者台词显示后可在10秒后自动隐藏。
6. 未治疗时使用治疗前立绘和治疗前台词。
7. 治疗成功时使用治疗后立绘和治疗后台词。
8. 治疗失败时保留治疗前立绘，显示治疗失败台词。

患者切换功能：

1. 普通 random 患者完成判定并关闭结果窗口后，替换为新的 random 患者。
2. story 患者治疗失败后保留在诊室，允许重新诊疗。
3. story 患者治疗成功后，优先检查 story_npc_cured 类型剧情。
4. 如果找到后续剧情，由 Main 接管剧情播放，不再生成普通患者。
5. 没有后续剧情时，恢复普通 random 患者流程。

诊室时辰功能：

1. Clinic 进入后启动白天计时。
2. 顶部栏随 GameTime 刷新当前时辰。
3. 剧情覆盖期间暂停诊室计时。
4. 剧情返回 Clinic 后恢复原有计时进度。
5. 诊室时辰耗尽或开发测试按钮要求结束当天时，停止诊室计时。
6. Clinic 只发出一次 clinic_finished，防止计时结束和按钮操作同时触发两次切场景。

============================================================
四、PulseWindow 脉诊窗口
============================================================

场景职责：

1. 显示当前患者的左右手脉象。
2. 把键盘脉诊按键映射到左右手寸、关、尺。
3. 根据疾病数据绘制相应脉象曲线。
4. 在松开脉诊按键后回到按键提示页。

打开和关闭：

1. 在 Clinic 或剧情诊疗中按 F1 打开。
2. 通过关闭按钮关闭。
3. 打开其他诊疗窗口时，由窗口控制器调整当前窗口层级。

窗口标签页：

1. 按键提示。
2. 右手脉象。
3. 左手脉象。

脉位和按键：

1. Q：右尺，对应肾阳。
2. A：右关，对应脾。
3. Z：右寸，对应肺。
4. W：左尺，对应肾阴。
5. S：左关，对应肝。
6. X：左寸，对应心。

显示规则：

1. 按下右手按键时切到右手脉象页。
2. 按下左手按键时切到左手脉象页。
3. 同一手的寸、关、尺曲线按照当前疾病的脉象数据刷新。
4. 画面同时保留浮脉等脉层提示，帮助玩家把脉位与脏腑对应起来。
5. 所有脉诊按键松开后回到按键提示页。
6. 没有有效患者或疾病数据时清空脉象显示，不进行诊断判定。

============================================================
五、PrescriptionWindow 断病与开方窗口
============================================================

场景职责：

1. 让玩家选择判断出的疾病。
2. 让玩家搜索药材并填写剂量单位。
3. 按君、臣、佐、使四个配伍区域组织处方。
4. 校验断病和处方是否为空。
5. 把提交请求交给 Clinic 的统一判定流程。

断病区域：

1. 显示疾病搜索输入框。
2. 显示可用疾病列表。
3. 支持通过疾病名称、疾病ID及标准化首字母进行筛选。
4. 点击疾病后写入当前处方的 disease_id 和 disease_name。
5. 清除选择时同步清空当前处方的疾病信息。

开方区域：

1. 显示药材搜索框和药材网格。
2. 支持药材名称、药材ID和ID首字母搜索。
3. 显示君、臣、佐、使四个处方区域。
4. 数字键1、2、3、4分别切换君、臣、佐、使区域。
5. 当前选中区域使用高亮样式。
6. 单位下拉框决定本次增加药材时使用的剂量单位。
7. 左键点击药材，把一个当前单位的剂量加入所选区域。
8. 再次点击同一药材时按底层统一剂量继续累加。
9. 右键点击药材时减少剂量；减至0时从处方移除。
10. 点击四区中的已有药材可选择该药材，右键可从对应区域移除。
11. “清空处方”删除当前全部药材。
12. “提交处方”把处方送往 Clinic 判定。

提交前校验：

1. 当前没有患者时禁止提交。
2. 患者没有绑定疾病时禁止提交。
3. 玩家处方为空时禁止提交。
4. 玩家没有选择断病结果时，由开方窗口提示补充断病。
5. 没有找到患者疾病对应的标准方时禁止判定。
6. 校验失败时通过提示窗口显示原因，不进入结果场景。

============================================================
六、处方判定与治疗结算
============================================================

判定输入：

1. 患者真实疾病。
2. 疾病对应的标准方剂。
3. 玩家选择的疾病。
4. 玩家提交的君、臣、佐、使药材和剂量。

当前评级规则：

1. 100分：妙手回春。
2. 60至99分：治疗成功。
3. 0至59分：治疗失败。

名望和心得规则：

1. 妙手回春：名望增加10，心得增加1。
2. 治疗成功：名望和心得不变。
3. 治疗失败：名望减少10，心得不增加。
4. 同一名患者重复提交处方时，不重复增加或扣除名望。
5. 同一名患者重复达到妙手回春时，不重复获得心得。
6. 心得变化后立即检查按累计心得自动解锁的条目。
7. 新条目解锁后立即刷新行医记考并保存。

患者状态规则：

1. 妙手回春和治疗成功都把患者标记为治疗成功。
2. 治疗失败把患者标记为失败状态。
3. 先在诊室显示治疗后或失败台词，再显示结果判定窗口。

============================================================
七、JudgementResult 判定结果窗口
============================================================

场景职责：

1. 汇总标准答案和玩家答案。
2. 显示治疗评级图片。
3. 显示本次新解锁的知识条目。
4. 阻止结果显示期间继续操作诊室。

显示内容：

1. 病人的真实疾病。
2. 标准方名称。
3. 标准方的君、臣、佐、使配伍内容。
4. 玩家选择的断病结果。
5. 玩家提交的处方内容。
6. 本次心得带来的新解锁条目。
7. 妙手回春、治疗成功或治疗失败评级图片。

交互规则：

1. 窗口打开时暂停场景树，避免后台继续计时或响应诊室操作。
2. 玩家点击任意区域后关闭结果窗口并恢复游戏。
3. 普通患者关闭结果后刷新下一名患者。
4. 剧情患者关闭结果后根据治疗成功或失败继续当前剧情诊疗流程。

============================================================
八、ClinicalLogWindow 行医记考窗口
============================================================

场景职责：

1. 供玩家在诊疗时查阅已经解锁的知识。
2. 分别展示疾病、方剂和药材条目。
3. 提供搜索、详情显示和古籍式分页。

打开和关闭：

1. 在 Clinic 或剧情诊疗中按 F3 打开。
2. 关闭窗口后回到原有诊疗画面。
3. 解锁状态发生变化后可以刷新列表。

疾病页：

1. 左侧显示已经解锁的疾病列表。
2. 搜索框筛选疾病条目。
3. 右侧显示选中疾病的详细内容。
4. 内容过长时使用上一页、下一页和页码切换。

方剂页：

1. 左侧显示已经解锁的方剂列表。
2. 搜索框筛选方剂条目。
3. 右侧显示选中方剂的详细内容。
4. 内容过长时使用上一页、下一页和页码切换。

药材页：

1. 左侧显示已经解锁的药材列表。
2. 搜索框筛选药材条目。
3. 右侧显示选中药材的详细内容。
4. 内容过长时使用上一页、下一页和页码切换。

搜索与排版规则：

1. 搜索按条目标题、数据ID及标准化首字母匹配。
2. 当前只显示 Unlock 中已经可查阅的条目。
3. 详情优先使用数据表中的 detail_text。
4. 古书竖排组件按真实可见列数分页，避免正文底部被裁切。
5. 如果详情节点没有竖排组件，则退回按字符数分页。

============================================================
九、Night 夜晚场景
============================================================

场景职责：

1. 显示当天夜晚状态。
2. 提供医书阅读入口。
3. 检查是否仍有未读的新条目。
4. 满足休息条件后结束夜晚并进入下一天。
5. 在进入夜晚时检查 trigger_scene = night 的自动剧情。

主界面可见内容：

1. 夜晚背景。
2. 顶部栏：天数、时辰、名望、心得。
3. “读书”按钮。
4. “进入明天”按钮。
5. 通用提示窗口。

进入夜晚流程：

1. Main 完成白天状态变更并保存。
2. Night 刷新天数、时辰、名望和心得。
3. 检查当前天数是否存在夜晚自动剧情。
4. 有剧情时向 Main 发出 story_requested。
5. 没有剧情或剧情结束后，玩家停留在夜晚主界面。

进入明天规则：

1. 点击“进入明天”时刷新当前心得和依赖关系可能带来的新解锁。
2. 检查药材、方剂、疾病、理论四类是否仍有已解锁但未查看的可读条目。
3. 如果仍有未读条目，显示“尚有未读条目，请先阅读后再休息”，不进入下一天。
4. 所有可读新条目都已查看后发出 night_finished。
5. Main 调用 GameTime.finish_night()，天数增加1，切换为白天。
6. Main 保存新一天状态并进入 Clinic。

============================================================
十、ReadBook 医书阅读窗口
============================================================

场景职责：

1. 显示当前可见的医书。
2. 显示每本书中已经解锁的条目。
3. 标识未读条目。
4. 玩家第一次查看条目时将其标记为已读。
5. 触发相关药材和依赖知识同步解锁。
6. 阅读状态变化后立即保存。

窗口布局：

1. 左栏：医书列表。
2. 中栏：所选医书的条目列表。
3. 右栏：所选条目的正文。
4. 底部：当前阅读提示和累计心得。

医书列表规则：

1. 只显示 Unlock 判定为可见的医书。
2. 某本书有未读条目时，在书名后显示“【新N】”。
3. 有新条目的书使用醒目颜色，并显示新条目数量提示。
4. 重新刷新列表时尽量保持原来选择的书。

条目列表规则：

1. 只显示当前书中已经满足可读条件的条目。
2. 未读条目排在已读条目前面。
3. 进入某本书后不自动阅读第一条，必须由玩家手动点击。
4. 当前没有可读条目时，显示该书暂无已解锁条目和当前累计心得。

阅读规则：

1. 点击条目后再次检查它是否已经解锁或曾经读过。
2. 不满足条件时不显示正文，并提示需要先满足解锁条件。
3. 第一次查看时调用 Unlock.read_entry() 标记为已读。
4. 药材条目在第一次查看时同步解锁对应药材。
5. 方剂和疾病通常通过依赖关系提前解锁，阅读时主要完成“已读”登记。
6. 阅读后立即保存，并通知 Night 刷新顶部栏和未读状态。
7. 正文优先显示条目 detail_text；没有正文时显示“暂无正文”。
8. 阅读后刷新书名的新条目数量，同时保持当前书和当前条目选择。

============================================================
十一、Story 剧情场景
============================================================

场景职责：

1. 播放 StoryData 中的对话和字幕行。
2. 切换剧情背景和人物立绘。
3. 支持打字机文字效果和剧情跳过。
4. 在剧情要求诊疗时打开把脉、开方和行医记考。
5. 把剧情结束、后续剧情、诊疗请求和 Game Over 请求发送给 Main。

画面结构：

1. 全屏剧情背景。
2. 半透明暗色遮罩。
3. 左、中、右三个角色立绘位置。
4. 对话框模式：角色名、对话正文和继续提示。
5. 字幕模式：居中背景字幕和继续提示。
6. 剧情诊疗按钮区：把脉、开方、行医记考。
7. 脉诊、处方、行医记考和结果判定窗口。

台词播放规则：

1. 每段新剧情先应用默认背景。
2. 单句 StoryLine 可以覆盖当前背景。
3. 对话行显示说话人姓名和正文。
4. 字幕行隐藏普通对话框，使用居中字幕区域。
5. 当前说话人的立绘正常显示，其他角色可按数据设置正常、压暗或隐藏。
6. 立绘可以放在左、中、右三个位置。
7. 文本按 type_speed 逐字显示。
8. 文本尚未显示完时，点击或按空格先立即显示完整本句。
9. 本句已经完整显示时，点击或按空格进入下一句。
10. 长按回车约1秒可以跳过整段剧情。
11. 剧情到达最后一行后进入正式结束处理。

一次性剧情规则：

1. 每段剧情使用稳定的 story_id 判断播放记录。
2. play_once 为 true 且已经播放过时，Main 直接跳过。
3. 剧情开始时不立即标记为已播放。
4. 只有收到正式结束信号时才标记当前剧情。
5. 连续剧情切换时，上一段必须完整播放后才登记为已播放。

剧情内诊疗流程：

1. StoryData 配置 clinic_npc_id 后，普通台词播放完毕时发出诊疗请求。
2. Main 在不可见的 StoryTreatmentBackendRoot 中创建 Clinic 实例。
3. 隐藏 Clinic 负责准备指定 story NPC、疾病、处方和评分后端。
4. Story 继续保持在最上层显示，不切回普通 Clinic 画面。
5. Story 显示“把脉（F1）”“开方（F2）”“行医记考（F3）”。
6. 三个窗口与普通诊室共用相同数据和操作规则。
7. 玩家提交处方后，隐藏 Clinic 返回判定结果。
8. Story 关闭诊疗窗口，显示 JudgementResult。
9. 关闭结果窗口后，根据成功或失败状态继续已经配置好的后续剧情或返回流程。

剧情结束类型：

1. 普通剧情：发出 story_finished，由 Main 标记已播放、保存并返回目标场景。
2. 剧情诊疗成功：可触发已经配置的 story_npc_cured 后续剧情。
3. story_npc_failed_back：失败剧情播放完毕后发出 story_finished，按 return_scene 返回。
4. story_npc_failed_over：失败剧情播放完毕后发出 game_over_requested。
5. Game Over 返回主菜单，不写入本次失败后的状态，保留最后一个可读取存档点。

剧情返回规则：

1. return_scene = clinic：回到诊室并恢复或重建白天流程。
2. return_scene = night：结束白天状态，保存后进入夜晚。
3. return_scene = map：当前没有 Map.tscn，会警告并退回 Clinic。
4. return_scene 为空时优先使用 trigger_scene；仍为空则默认 clinic。

十二、PlayerHintWindow 通用提示窗口
============================================================

场景职责：

2. 用于开方校验、夜晚未读提醒等流程。

十三、InfoWindow 开发测试窗口
============================================================

定位：

1. 该窗口位于 Scene/Test，不属于正式玩家核心界面。
2. 用于开发阶段快速验证诊室流程。

当前测试功能：

十四、场景间信号和结果对应关系
============================================================

1. Clinic.clinic_finished
   发送方：Clinic
   接收方：Main
   结果：结束白天、保存、进入 Night。

2. Clinic.story_requested
   发送方：Clinic
   接收方：Main
   结果：暂停诊室计时并播放 Story 覆盖层。

3. Night.night_finished
   发送方：Night
   接收方：Main
   结果：结束夜晚、天数加1、保存、进入 Clinic。

4. Night.story_requested
   发送方：Night
   接收方：Main
   结果：播放夜晚剧情。

5. Story.story_finished
   发送方：Story
   接收方：Main
   结果：标记剧情已播放、保存并返回目标场景。

6. Story.story_treatment_requested
   发送方：Story
   接收方：Main
   结果：创建隐藏 Clinic 诊疗后端。

7. Story.followup_story_requested
   发送方：Story
   接收方：Main
   结果：登记上一段剧情并切换到后续 StoryData。

8. Story.game_over_requested
   发送方：Story
   接收方：Main
   结果：不保存失败状态，回到主菜单。

9. PrescriptionWindow.submit_requested
   发送方：PrescriptionWindow
   接收方：Clinic 或 Story
   结果：执行统一处方判定。

10. ReadBook.player_data_changed
    发送方：ReadBook
    接收方：Night
    结果：刷新心得、未读数量和解锁状态。

十五、当前场景功能验收清单
============================================================

1. 新游戏选择空槽后，应创建存档并进入第1天 Clinic。
2. 新游戏选择已有槽后，应先弹出覆盖确认；取消后原存档保持不变。
3. 白天存档读取后应进入 Clinic，夜晚存档读取后应进入 Night。
4. Clinic 第1、7、13、19、25天应分别显示春、夏、秋、冬、春背景。
5. Clinic 没有自动剧情时应生成 random 患者。
6. F1、F2、F3应分别打开把脉、开方和行医记考。
7. Q、A、Z应显示右尺、右关、右寸；W、S、X应显示左尺、左关、左寸。
8. 未选疾病或处方为空时，应阻止提交并显示明确提示。
9. 100分应显示妙手回春，名望+10、心得+1，并且同一患者不能重复获得。
10. 60至99分应显示治疗成功，名望和心得不变。
11. 0至59分应显示治疗失败，名望-10，story 患者保留并允许重试。
12. 关闭普通患者的结果窗口后，应自动刷新下一名 random 患者。
13. 行医记考只能看到已经解锁的疾病、方剂和药材条目。
14. Night 存在未读条目时，“进入明天”应被阻止。
15. ReadBook 只有在玩家手动点击条目后才标记已读并保存。
16. 所有可读条目查看完毕后，“进入明天”应使天数加1并回到 Clinic。
17. 一次性剧情完整结束后应记录播放状态；剧情中途退出不应提前记为完成。
18. 剧情进入 night 时，应先更新为夜晚状态再保存，避免重复存档产生不完整状态。
19. Game Over 后应回到主菜单，并能读取 Game Over 前最后一个存档点。
20. return_scene = map 时，由于地图场景尚不存在，应安全退回 Clinic，不能崩溃。

============================================================
十六、当前边界与已知状态
============================================================

1. 核心场景循环已经贯通：Main → Clinic → Night → 下一天。
2. Clinic 的接诊、把脉、开方、评分、治疗反馈和患者刷新已有可运行框架。
3. Night 的读书、未读检查和进入下一天已有完整流程。
4. Story 支持普通对话、字幕、立绘、背景、剧情诊疗、连续剧情和 Game Over。
5. Map 场景仍未实现，当前只有安全回退逻辑。
6. 存档已经采用临时文件、正式档和备份恢复流程。
7. 存档恢复失败时，主菜单槽位仍可能被显示成“空存档”，属于当前已知界面提示问题。
8. 新版1号槽存档和旧版 save_game.json 同时存在时，删除新版槽位可能留下旧存档；当前正常游戏流程没有调用删除接口。
9. 当前检查以代码和场景静态结构为依据，尚未完成 Godot 引擎内的全流程运行测试。
