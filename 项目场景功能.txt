============================================================
一、项目场景总流程
============================================================

1. 游戏启动后进入 Main 主场景。
2. 玩家选择“新游戏”“读取存档”或“退出游戏”。
3. 新游戏或读取白天存档后进入 Clinic 诊室场景。
4. 白天在诊室接诊 random 患者，完成把脉、断病、开方并查看治疗结果。
5. Clinic 或 Night 进入时先检查满足场景、天数、前置剧情、名望和知识条件的自动剧情。
6. 普通剧情可在台词结束后直接进入 story NPC 诊疗；Story 保持在表现层，隐藏 Clinic 只提供诊疗后端。
7. 白天结束后进入 Night 夜晚场景。
8. 夜晚阅读已经解锁的医书条目。
9. 当晚所有可读新条目都已查看后，玩家可以进入下一天。
10. Story 支持普通结束、治疗成功、失败重试、失败返回和失败 Game Over 等分支。
11. 剧情结束后，根据剧情数据返回诊室或夜晚；Game Over 剧情返回主菜单。
12. 白天结束、夜晚结束、剧情切换、剧情成长结算和重要知识变化时写入当前存档槽。

当前主要可用场景：

1. Main：主菜单、存档槽、场景调度和自动存档。
2. Clinic：白天接诊和诊疗主场景。
3. PulseWindow：脉诊窗口。
4. PrescriptionWindow：断病与开方窗口。
5. ClinicalLogWindow：行医记考窗口。
6. JudgementResult：处方判定结果窗口。
7. Night：夜晚主场景。
8. ReadBook：医书阅读窗口。
9. Story：剧情播放及剧情诊疗场景。
10. PlayerHintWindow：通用提示窗口。
11. InfoWindow：Clinic 与 Night 共用的 Debug 开发测试窗口，不属于正式玩家流程。

Map 只在 Main 中保留了加载入口，当前仓库没有 Scene/Map/Map.tscn。剧情返回目标如果填写 map，系统会警告并退回 Clinic，不能视为已经完成的地图场景。

============================================================
二、Main 主场景
============================================================

场景职责：

1. 作为整个游戏的常驻根场景。
2. 显示开始菜单。
3. 管理三个存档槽。
4. 创建、隐藏、清理和切换 Clinic、Night、Story 等子场景。
5. 接收白天结束、夜晚结束和剧情结束信号。
6. 在关键流程节点调用 SaveManager 保存。
7. 保证剧情播放时不直接销毁当前诊室或夜晚场景。
8. 在隐藏 Clinic 或 Night 前取得当前实际季节背景，并把贴图注入 Story。
9. 接收剧情台词完成通知，按 StoryData 结算剧情名望与心得变化。

主要界面：

1. 游戏标题区域。
2. “新游戏”按钮。
3. “读取存档”按钮。
4. “退出游戏”按钮。
5. 三槽存档选择弹窗。
6. 覆盖旧存档确认框。

新游戏流程：

1. 点击“新游戏”。
2. 打开三个存档槽。
3. 空槽显示“新游戏槽位N／空存档”，允许直接选择。
4. 已有存档的槽位显示存档名称和保存时间。
5. 选择已有存档时弹出覆盖确认。
6. 取消覆盖后返回槽位选择。
7. 确认后设置当前槽位，重置游戏时间、知识解锁进度和剧情播放记录。
8. 先尝试安全写入新档；写入失败时保留原存档，不进入游戏。
9. 写入成功后隐藏主菜单，进入第1天 Clinic。

读取存档流程：

1. 点击“读取存档”。
2. 三个槽位读取存档摘要。
3. 有存档的槽位显示游戏进度名称和保存时间，并允许点击。
4. 空槽显示“空存档”，按钮不可点击。
5. 读取成功后根据 GameTime 中的昼夜状态决定场景：白天进入 Clinic，夜晚进入 Night。
6. 读取失败时留在槽位界面，不进入子场景。

退出游戏流程：

1. 点击“退出游戏”。
2. 直接调用 Godot 退出游戏。
3. 当前代码不会在退出按钮被点击时额外强制保存，因此玩家状态依赖之前的自动存档节点。

子场景挂载结构：

1. CurrentSceneRoot：放置当前 Clinic、Night 或 Map 实例。
2. StorySceneRoot：放置正在播放的 Story 覆盖层。
3. StoryTreatmentBackendRoot：放置剧情诊疗所需的隐藏 Clinic 后端。

Clinic 进入处理：

1. 清理旧的普通子场景。
2. 实例化 Clinic。
3. 先连接 clinic_finished 和 story_requested 信号。
4. 设置当前天数。
5. 调用 start_new_day()，开始当天自动剧情检查或生成日常患者。

Night 进入处理：

1. 清理旧的普通子场景。
2. 实例化 Night。
3. 先连接 night_finished 和 story_requested 信号。
4. 调用 start_night()，刷新夜晚状态并检查夜晚自动剧情。

剧情覆盖处理：

1. Clinic 或 Night 发送 story_requested。
2. Main 加载 StoryData，并检查 story_id、play_once 和是否已经播放。
3. 读取 StoryData.return_scene 作为剧情结束后的返回目标。
4. 从诊室触发剧情时暂停诊室计时，但保留已经经过的时辰进度。
5. 在进入剧情前保存一次当前状态。
6. 隐藏当前 Clinic 或 Night 画面前读取其 get_current_background_texture() 返回值。
7. 把背景贴图注入 Story 后再挂载 Story 场景，避免 Story._ready() 抢先播放。
8. 隐藏当前 Clinic 或 Night 画面，不立即销毁。
9. Story 每一段台词真正播放完或被跳过到结尾时发送 story_playback_completed。
10. Main 收到 story_playback_completed 后，按 StoryData.reputation_points_change 和 experience_points_change 结算成长。
11. 非 Game Over 剧情发生成长变化时立即保存；Game Over 只改变内存，不覆盖最后可读存档。
12. 剧情真正结束后才把当前 story_id 记为已播放，并记录首次完成时的游戏天数。
13. 连续剧情切换前，先把上一段完整播放的剧情记为已播放。
14. 普通剧情结束后保存，再回到配置的目标场景。
15. 返回 night 时先结束白天，再保存完整的夜晚状态，最后进入 Night。
16. Game Over 剧情结束后不覆盖磁盘存档，清理本局临时状态并回到主菜单。

Main 的主要自动存档节点：

1. 新游戏创建成功时。
2. 进入剧情前。
3. 切换到普通后续剧情时。
4. 普通剧情真正结束时。
5. 白天 Clinic 结束时。
6. 夜晚 Night 结束时。
7. random 患者诊疗获得名望、心得或解锁内容时，由 Clinic 即时保存。
8. 非 Game Over 剧情完整播放并产生名望或心得变化时。
9. Debug 测试窗口修改日期、剧情状态、名望、心得或阅读状态时。

============================================================
三、Clinic 白天诊室场景
============================================================

场景职责：

1. 显示当前日期、时辰、名望和心得。
2. 按当前天数切换诊室季节背景。
3. 生成和显示患者。
4. 提供把脉、断病、开方和行医记考入口。
5. 调用方剂判定系统进行治疗评分。
6. 更新患者治疗前、治疗成功或治疗失败状态。
7. 为 random 患者发放固定名望、心得和新条目解锁。
8. 在隐藏后端模式中为 Story 提供 story NPC、处方和评分能力。
9. 诊室时间结束后通知 Main 进入夜晚。
10. 以淡入淡出方式切换诊室季节背景，并向 Main 暴露当前背景贴图。

主界面可见内容：

1. 诊室背景图。
2. 桌案前的患者立绘。
3. 患者姓名。
4. 患者当前台词。
5. 顶部栏：当前天数、当前时辰、名望、心得。
6. “把脉（F1）”按钮。
7. “开方（F2）”按钮。
8. “行医记考（F3）”按钮。
9. Debug 构建中可按 Ctrl+T 打开 InfoWindow；正式构建不响应该入口。

季节背景规则：

1. 每一天对应一个节气位置。
2. 24天为一轮。
3. 第1至第6天使用春季诊室背景。
4. 第7至第12天使用夏季诊室背景。
5. 第13至第18天使用秋季诊室背景。
6. 第19至第24天使用冬季诊室背景。
7. 第25天重新从春季开始循环。
8. 初次进入场景时从黑色渐入；季节贴图变化时先渐出到黑色、换图，再渐入。
9. 单次渐出或渐入默认0.45秒，完整换图约0.9秒。

当天开始流程：

1. Main 传入当前天数。
2. Clinic 更新季节背景。
3. 重置“当天已经结束”的防重复标记。
4. 刷新时辰、名望和心得显示。
5. 先查询 trigger_scene = clinic 且满足当前条件的自动剧情。
6. 如果触发剧情，先把请求交给 Main，不生成普通患者。
7. 没有自动剧情时，生成一名 random 类型患者；story NPC 只由 Story 的隐藏诊疗后端生成。

患者显示功能：

1. 显示患者姓名、立绘和台词。
2. random 患者进入时从左侧偏移200像素的位置滑入并由透明渐显，时长1秒，保持原始缩放。
3. 普通患者的疾病从当前已经解锁的疾病池中分配。
4. story 患者由 StoryData.clinic_npc_id 与 clinic_disease 共同指定，并在隐藏 Clinic 后端中生成。
5. 患者台词显示后可在10秒后自动隐藏。
6. 未治疗时使用治疗前立绘和治疗前台词。
7. 治疗成功时使用治疗后立绘和治疗后台词。
8. 治疗失败时保留治疗前立绘，显示治疗失败台词。

患者切换功能：

1. 普通 random 患者完成判定并关闭结果窗口后，替换为新的 random 患者。
2. 普通 Clinic 不再直接承载 story NPC；story NPC 的诊疗表现始终留在 Story 场景。
3. story NPC 治疗结束后，隐藏 Clinic 后端按“发起治疗的主剧情ID”查找成功或失败后续剧情。
4. 成功且没有后续剧情时结束当前剧情；失败且没有失败剧情时回到同一名 story NPC 的诊疗选项。
5. 失败重试剧情播放完后重置上一轮处方和提交状态，再回到同一名 story NPC 的诊疗选项。

诊室时辰功能：

1. Clinic 进入后启动白天计时。
2. 顶部栏随 GameTime 刷新当前时辰。
3. 剧情覆盖期间暂停诊室计时。
4. 剧情返回 Clinic 后恢复原有计时进度。
5. 诊室时辰耗尽或开发测试按钮要求结束当天时，停止诊室计时。
6. Clinic 只发出一次 clinic_finished，防止计时结束和按钮操作同时触发两次切场景。

日期与时辰显示规则：

1. current_day = 1 实际显示为“嘉靖二十年立春”。
2. 每一天推进一个节气，24个节气为一年。
3. 嘉靖年号从二十年推进到四十五年，之后切换为万历元年。
4. 白天诊室从辰时开始，到申时结束。
5. 现实60秒对应游戏内1个时辰。
6. 夜晚结束时 current_day 才增加1；白天结束只把阶段切换为 Night。

============================================================
四、PulseWindow 脉诊窗口
============================================================

场景职责：

1. 显示当前患者的左右手脉象。
2. 把键盘脉诊按键映射到左右手寸、关、尺。
3. 根据疾病数据绘制相应脉象曲线。
4. 在松开脉诊按键后回到按键提示页。

打开和关闭：

1. 在 Clinic 或剧情诊疗中按 F1 打开。
2. 通过关闭按钮关闭。
3. 打开其他诊疗窗口时，由窗口控制器调整当前窗口层级。

窗口标签页：

1. 按键提示。
2. 右手脉象。
3. 左手脉象。

脉位和按键：

1. Q：右尺，对应肾阳。
2. A：右关，对应脾。
3. Z：右寸，对应肺。
4. W：左尺，对应肾阴。
5. S：左关，对应肝。
6. X：左寸，对应心。

显示规则：

1. 按下右手按键时切到右手脉象页。
2. 按下左手按键时切到左手脉象页。
3. 同一手的寸、关、尺曲线按照当前疾病的脉象数据刷新。
4. 画面同时保留浮脉等脉层提示，帮助玩家把脉位与脏腑对应起来。
5. 所有脉诊按键松开后回到按键提示页。
6. 没有有效患者或疾病数据时清空脉象显示，不进行诊断判定。

============================================================
五、PrescriptionWindow 断病与开方窗口
============================================================

场景职责：

1. 让玩家选择判断出的疾病。
2. 让玩家搜索药材并填写剂量单位。
3. 按君、臣、佐、使四个配伍区域组织处方。
4. 校验断病和处方是否为空。
5. 把提交请求交给 Clinic 的统一判定流程。

断病区域：

1. 显示疾病搜索输入框。
2. 显示可用疾病列表。
3. 支持通过疾病名称、疾病ID及标准化首字母进行筛选。
4. 点击疾病后写入当前处方的 disease_id 和 disease_name。
5. 清除选择时同步清空当前处方的疾病信息。

开方区域：

1. 显示药材搜索框和药材网格。
2. 支持药材名称、药材ID和ID首字母搜索。
3. 显示君、臣、佐、使四个处方区域。
4. 数字键1、2、3、4分别切换君、臣、佐、使区域。
5. 当前选中区域使用高亮样式。
6. 单位下拉框决定本次增加药材时使用的剂量单位。
7. 左键点击药材，把一个当前单位的剂量加入所选区域。
8. 再次点击同一药材时按底层统一剂量继续累加。
9. 右键点击药材时减少剂量；减至0时从处方移除。
10. 点击四区中的已有药材可选择该药材，右键可从对应区域移除。
11. “清空处方”删除当前全部药材。
12. “提交处方”把处方送往 Clinic 判定。

提交前校验：

1. 当前没有患者时禁止提交。
2. 患者没有绑定疾病时禁止提交。
3. 玩家处方为空时禁止提交。
4. 玩家没有选择断病结果时，由开方窗口提示补充断病。
5. 没有找到患者疾病对应的标准方时禁止判定。
6. 校验失败时通过提示窗口显示原因，不进入结果场景。

============================================================
六、处方判定与治疗结算
============================================================

判定输入：

1. 患者真实疾病。
2. 疾病对应的标准方剂。
3. 玩家选择的疾病。
4. 玩家提交的君、臣、佐、使药材和剂量。

当前评级规则：

1. 100分：妙手回春。
2. 60至99分：治疗成功。
3. 0至59分：治疗失败。

random 患者名望和心得规则：

1. 妙手回春：名望增加10，心得增加1。
2. 治疗成功：名望和心得不变。
3. 治疗失败：名望减少10，心得不增加。
4. 同一名患者重复提交处方时，不重复增加或扣除名望。
5. 同一名患者重复达到妙手回春时，不重复获得心得。
6. 心得变化后立即检查按累计心得自动解锁的条目。
7. 新条目解锁后立即刷新行医记考并保存。
8. 判定结果窗口会显示本次 random 患者实际发生的名望和心得变化。

story NPC 成长结算规则：

1. story NPC 在处方判定时不使用 random 患者固定奖励与惩罚。
2. 治疗结果先决定成功或失败后续剧情，不在判定瞬间结算成长。
3. 后续剧情完整播放后，按该 StoryData 的 reputation_points_change 和 experience_points_change 结算。
4. 剧情名望和心得均允许正数、负数或0；心得最低保持为0，已经解锁的条目不会重新锁回。
5. 剧情增加心得时同样会检查累计心得自动解锁，并返回新解锁条目标题。
6. 当前资源中004_02奖励心得+5，005_02奖励名望+1000和心得+5；其他已配置剧情变化量为0。
7. story NPC 的即时判定结果窗口不显示固定奖励变化，避免与后续剧情结算重复。
8. Game Over 剧情即使配置成长变化，也不覆盖磁盘上的最后可读取存档。

患者状态规则：

1. 妙手回春和治疗成功都把患者标记为治疗成功。
2. 治疗失败把患者标记为失败状态。
3. 先在诊室显示治疗后或失败台词，再显示结果判定窗口。

============================================================
七、JudgementResult 判定结果窗口
============================================================

场景职责：

1. 汇总标准答案和玩家答案。
2. 显示治疗评级图片。
3. 显示本次新解锁的知识条目。
4. 阻止结果显示期间继续操作诊室。
5. 对 random 患者显示本次名望与心得变化。
6. 关闭时通过显式 result_closed 信号推进后续流程。

显示内容：

1. 病人的真实疾病。
2. 标准方名称。
3. 标准方的君、臣、佐、使配伍内容。
4. 玩家选择的断病结果。
5. 玩家提交的处方内容。
6. 本次心得带来的新解锁条目。
7. 妙手回春、治疗成功或治疗失败评级图片。
8. random 患者本次治疗的名望、心得变化；story NPC 该区域隐藏。

交互规则：

1. 窗口打开时暂停场景树，避免后台继续计时或响应诊室操作。
2. 玩家点击任意区域后关闭结果窗口并恢复游戏，result_closed 只发送一次。
3. 普通患者关闭结果后刷新下一名 random 患者。
4. story NPC 关闭结果后，由隐藏 Clinic 后端根据发起治疗的主剧情ID查找成功或失败后续剧情。

九、Night 夜晚场景
============================================================

场景职责：

1. 显示当天夜晚状态。
2. 提供医书阅读入口。
3. 检查是否仍有未读的新条目。
4. 满足休息条件后结束夜晚并进入下一天。
5. 在进入夜晚时检查 trigger_scene = night 的自动剧情。
6. 根据当前节气显示独立的春、夏、秋、冬夜景，并以淡入淡出方式切换。
7. Debug 构建中承载 InfoWindow，供快速修改测试状态和跨天验证。

主界面可见内容：

1. 夜晚背景。
2. 顶部栏：天数、时辰、名望、心得。
3. “读书”按钮。
4. “进入明天”按钮。
5. 通用提示窗口。
6. Debug 构建中按 Ctrl+T 打开的 InfoWindow。

夜晚季节背景规则：

1. 与 Clinic 共用24天季节划分：1至6天春、7至12天夏、13至18天秋、19至24天冬。
2. 第25天重新从春季夜景开始循环。
3. 初次进入 Night 时从黑色渐入。
4. 季节变化时先渐出到黑色、替换贴图，再渐入；单段默认0.45秒。
5. Night 向 Main 提供 get_current_background_texture()，供 current_scene 模式剧情复用当前夜景。

进入夜晚流程：

1. Main 完成白天状态变更并保存。
2. Night 根据传入天数更新夜晚季节背景。
3. Night 刷新天数、时辰、名望和心得。
4. 检查当前天数是否存在满足全部条件的夜晚自动剧情。
5. 有剧情时向 Main 发出 story_requested。
6. 没有剧情或剧情结束后，玩家停留在夜晚主界面。

进入明天规则：

1. 点击“进入明天”时刷新当前心得和依赖关系可能带来的新解锁。
2. 检查药材、方剂、疾病、理论四类是否仍有已解锁但未查看的可读条目。
3. 如果仍有未读条目，显示“尚有未读条目，请先阅读后再休息”，不进入下一天。
4. 所有可读新条目都已查看后发出 night_finished。
5. Main 调用 GameTime.finish_night()，天数增加1，切换为白天。
6. Main 保存新一天状态并进入 Clinic。

Debug 快捷流程：

1. Ctrl+T 只在 Debug 构建且 Night 可见时打开 InfoWindow。
2. Night 中的“结束当天”会直接发送 night_finished，故意跳过未读条目检查，便于测试跨天。
3. Night 没有当前病人，切换、生成病人的测试按钮只显示不可用提示。
4. 一键解锁或阅读条目后刷新顶部栏和读书列表。

十、ReadBook 医书阅读窗口
============================================================

场景职责：

1. 显示当前可见的医书。
2. 显示每本书中已经解锁的条目。
3. 标识未读条目。
4. 玩家第一次查看条目时将其标记为已读。
5. 触发相关药材和依赖知识同步解锁。
6. 阅读状态变化后立即保存。

窗口布局：

1. 左栏：医书列表。
2. 中栏：所选医书的条目列表。
3. 右栏：所选条目的正文。
4. 底部：当前阅读提示和累计心得。

医书列表规则：

1. 只显示 Unlock 判定为可见的医书。
2. 某本书有未读条目时，在书名后显示“【新N】”。
3. 有新条目的书使用醒目颜色，并显示新条目数量提示。
4. 重新刷新列表时尽量保持原来选择的书。

条目列表规则：

1. 只显示当前书中已经满足可读条件的条目。
2. 未读条目排在已读条目前面。
3. 进入某本书后不自动阅读第一条，必须由玩家手动点击。
4. 当前没有可读条目时，显示该书暂无已解锁条目和当前累计心得。

阅读规则：

1. 点击条目后再次检查它是否已经解锁或曾经读过。
2. 不满足条件时不显示正文，并提示需要先满足解锁条件。
3. 第一次查看时调用 Unlock.read_entry() 标记为已读。
4. 药材条目在第一次查看时同步解锁对应药材。
5. 方剂和疾病通常通过依赖关系提前解锁，阅读时主要完成“已读”登记。
6. 阅读后立即保存，并通知 Night 刷新顶部栏和未读状态。
7. 正文优先显示条目 detail_text；没有正文时显示“暂无正文”。
8. 阅读后刷新书名的新条目数量，同时保持当前书和当前条目选择。

============================================================
十一、Story 剧情场景
============================================================

场景职责：

1. 播放 StoryData 中的对话和字幕行。
2. 按 default 或 current_scene 模式准备开场背景，并切换 StoryLine 指定的背景和人物立绘。
3. 支持打字机文字效果和剧情跳过。
4. 在剧情要求诊疗时打开把脉、开方和行医记考。
5. 把台词播放完成、剧情结束、后续剧情、诊疗请求和 Game Over 请求发送给 Main。
6. 在剧情台词完整播放后触发 StoryData 配置的名望和心得结算。

画面结构：

1. 全屏剧情背景。
2. 半透明暗色遮罩。
3. 左、中、右三个角色立绘位置。
4. 对话框模式：角色名、对话正文和继续提示。
5. 字幕模式：居中背景字幕和继续提示。
6. 剧情诊疗按钮区：把脉、开方、行医记考。
7. 脉诊、处方、行医记考和结果判定窗口。

台词播放规则：

1. background_mode = default 时使用 Story 场景配置的默认背景。
2. background_mode = current_scene 时使用 Main 从当前 Clinic 或 Night 注入的实际季节背景。
3. 如果第一句已经指定背景，直接以第一句背景开场，避免默认背景闪现后再次换图。
4. 单句 StoryLine.background 非空时覆盖当前背景；留空时沿用上一句背景。
5. 初次背景从黑色渐入；换图时旧背景渐出到黑色、换图、新背景渐入。
6. 单次渐出或渐入默认0.45秒；背景过渡期间暂停台词推进并隐藏旧台词块与立绘。
7. 剧情结束时先渐出到黑色，再向 Main 发送结束、返回或 Game Over 信号。
8. 对话行显示说话人姓名和正文。
9. 字幕行隐藏普通对话框，使用居中字幕区域。
10. 当前说话人的立绘正常显示，其他角色可按数据设置 normal、dim 或 hide。
11. 立绘可以放在左、中、右三个位置；auto 或空位置会在左右两侧自动分配。
12. 同一 speaker 会复用既有站位与立绘映射；进入治疗结果剧情时只清除物理立绘槽，不清除人物映射。
13. 文本按 type_speed 逐字显示，底层使用完整文本配合 visible_characters，避免打字时容器抖动。
14. 文本尚未显示完时，点击或按空格先立即显示完整本句。
15. 本句已经完整显示时，点击或按空格进入下一句。
16. 长按回车约1秒可以跳过整段剧情。
17. 每次 play_story() 只上报一次 story_playback_completed，防止连按、跳过或连续剧情重复结算。

剧情触发条件：

1. StoryManager 启动时递归扫描 res://Data/Story 下的全部 .tres，并按资源路径排序。
2. 同一场景同时满足多个剧情时，优先播放路径排序靠前的第一个剧情。
3. trigger_type = scene_enter：进入 Clinic、Night 或未来 Map 时检查。
4. trigger_type = story_npc_cured：与指定主剧情的治疗成功结果匹配。
5. trigger_type = story_npc_failed_retry：失败剧情播放后回到同一名 story NPC 继续诊疗。
6. trigger_type = story_npc_failed_back：失败剧情播放后按 return_scene 返回。
7. trigger_type = story_npc_failed_over：失败剧情播放后 Game Over。
8. scene_enter 且 trigger_story_id 为空时，trigger_day 按游戏绝对天数判断。
9. scene_enter 且 trigger_story_id 非空时，trigger_day 按前置剧情首次完成日后的相对天数判断。
10. 治疗结果剧情必须填写 trigger_story_id，并且 trigger_day 必须为0，以便立即匹配本次治疗来源剧情。
11. required_reputation_points 大于0时，必须先由 Unlock 解锁对应 story_id，StoryManager 才允许播放。
12. unlock_entry_id 当前是“剧情触发前置医书条目”，不是剧情播放时自动赠送的条目；条目未解锁时剧情不触发。
13. play_once 为 true 且已播放的剧情不会再次触发；play_once 为 false 的剧情仍记录首次完成日，但可重复触发。

一次性剧情规则：

1. 每段剧情使用稳定的 story_id 判断播放记录。
2. play_once 为 true 且已经播放过时，Main 直接跳过。
3. 剧情开始时不立即标记为已播放。
4. 剧情台词播放完后先发送 story_playback_completed 结算成长，正式结束或连续剧情切换时再登记播放状态。
5. 连续剧情切换时，上一段必须完整播放后才登记为已播放。
6. 存档同时记录 played_story_ids 与 played_story_days；旧存档缺少完成日时按第0天兼容。

剧情内诊疗流程：

1. StoryData 配置 clinic_npc_id 后，普通台词播放完毕时发出诊疗请求。
2. StoryData.clinic_disease 配置本次剧情诊疗使用的疾病，疾病不再固定绑死在 story NPC 的 NpcData 上。
3. StoryData.clinic_npc_portrait 与 clinic_npc_portrait_side 单独配置诊疗选项阶段的立绘和位置。
4. Main 在不可见的 StoryTreatmentBackendRoot 中创建 Clinic 实例。
5. 隐藏 Clinic 负责按 clinic_npc_id、clinic_disease 准备 story NPC、处方和评分后端。
6. 同一个 story NPC 可在不同剧情中使用不同疾病。
7. Story 继续保持在最上层显示，不切回普通 Clinic 画面。
8. Story 显示“把脉（F1）”“开方（F2）”“行医记考（F3）”。
9. 三个窗口与普通诊室共用相同数据和操作规则。
10. 玩家提交处方后，隐藏 Clinic 返回判定结果。
11. Story 关闭诊疗窗口，显示 JudgementResult。
12. 关闭结果窗口后，以 treatment_source_story_id 查找成功或失败后续剧情。
13. 失败且没有配置失败剧情时，直接清空上一轮处方并回到同一名 story NPC 的诊疗选项。

剧情结束类型：

1. 普通剧情：发出 story_finished，由 Main 标记已播放、保存并返回目标场景。
2. 剧情诊疗成功：可触发已经配置的 story_npc_cured 后续剧情。
3. story_npc_failed_retry：失败剧情播放完毕后回到同一名 story NPC 的诊疗选项。
4. story_npc_failed_back：失败剧情播放完毕后发出 story_finished，按 return_scene 返回。
5. story_npc_failed_over：失败剧情播放完毕后发出 game_over_requested。
6. Game Over 返回主菜单，不写入本次失败后的状态，保留最后一个可读取存档点。

剧情返回规则：

1. return_scene = clinic：回到诊室并恢复或重建白天流程。
2. return_scene = night：结束白天状态，保存后进入夜晚。
3. return_scene = map：当前没有 Map.tscn，会警告并退回 Clinic。
4. return_scene 为空时优先使用 trigger_scene；仍为空则默认 clinic。

十三、InfoWindow 开发测试窗口
============================================================

定位：

1. 该窗口位于 Scene/Test，不属于正式玩家核心界面。
2. 用于开发阶段快速验证 Clinic、Night、剧情触发、成长和阅读流程。
3. 只允许在 Debug 构建中通过 Ctrl+T 打开，正式构建不会响应该快捷键。
4. Clinic 与 Night 场景中都固定实例化该窗口；NPC操作只在 Clinic 有效。

当前测试功能：

1. 切换到上一名患者。
2. 切换到下一名患者。
3. 生成 random 患者。
4. 立即结束当天。
5. 一键解锁所有医书条目。
6. 直接修改当前天数，并刷新日期、季节背景和顶部栏相关状态。
7. 列出全部剧情及其已播放/未播放状态，可手动把选中剧情标记为已播放。
8. 直接设置名望核心数值，并刷新名望剧情解锁状态。
9. 直接设置心得核心数值；增加心得时检查自动解锁，降低时最低为0且不回锁条目。
10. 一键阅读全部“已解锁且可读”的未读条目，并循环处理阅读带来的依赖解锁。
11. 显示当前天数、名望、心得和可读未读条目数量。
12. 测试修改完成后立即保存，并通知宿主场景刷新顶部栏和读书列表。

场景差异：

1. Clinic 中“结束当天”停止诊室计时并进入 Night。
2. Night 中“结束当天”直接结束夜晚，故意跳过未读检查进入下一天。
3. Night 中点击上一名、下一名或生成患者时只显示“该功能仅在 Clinic 可用”。
4. “一键解锁所有医书条目”会同时标记全部条目已读，并同步解锁药材、方剂、疾病和医理数据。

正式发布前应保持这些入口不被普通玩家误触，但本文件不对现有代码做删除或修改。

十五、场景间信号和结果对应关系
============================================================

1. Clinic.clinic_finished
   发送方：Clinic
   接收方：Main
   结果：结束白天、保存、进入 Night。

2. Clinic.story_requested
   发送方：Clinic
   接收方：Main
   结果：暂停诊室计时并播放 Story 覆盖层。

3. Night.night_finished
   发送方：Night
   接收方：Main
   结果：结束夜晚、天数加1、保存、进入 Clinic。

4. Night.story_requested
   发送方：Night
   接收方：Main
   结果：播放夜晚剧情。

5. Story.story_playback_completed
   发送方：Story
   接收方：Main
   结果：按当前 StoryData 结算名望与心得；非 Game Over 且发生变化时保存。

6. Story.story_finished
   发送方：Story
   接收方：Main
   结果：标记剧情已播放、保存并返回目标场景。

7. Story.story_treatment_requested
   发送方：Story
   接收方：Main
   结果：按 clinic_npc_id 与 clinic_disease 创建隐藏 Clinic 诊疗后端。

8. Story.followup_story_requested
   发送方：Story
   接收方：Main
   结果：登记上一段剧情并切换到后续 StoryData；失败重试时保留诊疗后端。

9. Story.game_over_requested
   发送方：Story
   接收方：Main
   结果：不保存失败状态，回到主菜单。

10. PrescriptionWindow.submit_requested
   发送方：PrescriptionWindow
   接收方：Clinic 或 Story
   结果：执行统一处方判定。

11. JudgementResult.result_closed
    发送方：JudgementResult
    接收方：Clinic 或 Story
    结果：只推进一次下一名 random 患者或剧情治疗结果分支。

12. ReadBook.player_data_changed
    发送方：ReadBook
    接收方：Night
    结果：刷新心得、未读数量和解锁状态。

13. InfoWindow.test_data_changed
    发送方：InfoWindow
    接收方：宿主测试流程
    结果：通知 Clinic 或 Night 刷新顶部栏、读书列表和当前测试状态。

十六、当前场景功能验收清单
============================================================

1. 新游戏选择空槽后，应创建存档并进入第1天 Clinic。
2. 新游戏选择已有槽后，应先弹出覆盖确认；取消后原存档保持不变。
3. 白天存档读取后应进入 Clinic，夜晚存档读取后应进入 Night。
4. Clinic 第1、7、13、19、25天应分别显示春、夏、秋、冬、春背景。
5. Night 第1、7、13、19、25天应分别显示春、夏、秋、冬、春夜景。
6. Clinic 与 Night 初次进入应从黑色渐入，季节换图应执行“渐出—换图—渐入”。
7. Clinic 没有自动剧情时应生成 random 患者。
8. random 患者立绘应从左侧滑入并渐显，快速切换患者时不应出现 Tween 累积偏移。
9. F1、F2、F3应分别打开把脉、开方和行医记考。
10. Q、A、Z应显示右尺、右关、右寸；W、S、X应显示左尺、左关、左寸。
11. 未选疾病或处方为空时，应阻止提交并显示明确提示。
12. random 患者100分应显示妙手回春、名望+10、心得+1，并且同一患者不能重复获得。
13. random 患者60至99分应显示治疗成功，名望和心得不变。
14. random 患者0至59分应显示治疗失败，名望-10。
15. story NPC 判定时不应直接使用 random 患者固定奖励，后续剧情播放完才按 StoryData 结算。
16. 关闭普通患者的结果窗口后，应通过 result_closed 自动刷新下一名 random 患者，且只刷新一次。
17. 关闭 story NPC 的结果窗口后，应按 treatment_source_story_id 匹配对应成功或失败剧情。
18. failed_retry 剧情结束后应清空上一轮处方并回到同一诊疗；没有失败剧情时也应直接允许重试。
19. 004_02完整播放后心得应+5；005_02完整播放后名望应+1000、心得应+5。
20. 行医记考只能看到已经解锁的疾病、方剂和药材条目。
21. Night 存在未读条目时，“进入明天”应被阻止。
22. ReadBook 只有在玩家手动点击条目后才标记已读并保存。
23. 所有可读条目查看完毕后，“进入明天”应使天数加1并回到 Clinic。
24. background_mode = current_scene 的剧情应显示触发场景当前季节背景；第一句另有背景时不得闪现默认背景。
25. 剧情换背景期间应暂停台词推进，结束时应淡出到黑色后再返回场景。
26. scene_enter 后续剧情的 trigger_day 应按前置剧情首次完成日计算；治疗结果剧情应保持 trigger_day = 0。
27. unlock_entry_id 未解锁时对应剧情不得触发；该字段本身不应自动赠送条目。
28. 一次性剧情完整结束后应记录 played_story_ids 和首次完成日；剧情中途退出不应提前记为完成。
29. 剧情进入 night 时，应先更新为夜晚状态再保存，避免重复存档产生不完整状态。
30. Game Over 后应回到主菜单，并能读取 Game Over 前最后一个存档点。
31. Debug 构建中 Clinic 与 Night 按 Ctrl+T 应打开 InfoWindow；正式构建不应开放该入口。
32. InfoWindow 修改日期、剧情状态、名望、心得或阅读状态后应保存并刷新宿主界面。
33. return_scene = map 时，由于地图场景尚不存在，应安全退回 Clinic，不能崩溃。
