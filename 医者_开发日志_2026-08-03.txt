4. 当前剧情与诊疗架构
============================================================
剧情触发类型：
- scene_enter：进入 clinic / night / map 时按天数、名望、前置条目等条件检查。
- story_npc_cured：指定剧情 NPC 治愈后触发。
- story_npc_treatment_failed：指定剧情 NPC 治疗失败后触发。

剧情 NPC 诊疗流程：
1. StoryData.clinic_npc_id 指定需要诊疗的 story NPC。
2. Main 创建隐藏的 Clinic 业务后端。
3. Story 场景保留画面表现，并开放把脉、开方、行医记考。
4. Clinic 后端复用普通诊疗的病人数据、处方评分、奖励和结算逻辑。
5. 判定后根据结果查找 story_npc_cured 或 story_npc_treatment_failed 剧情。
6. 成功可进入后续剧情；失败可播放失败剧情并继续治疗同一 NPC。

剧情立绘状态：
- dim：本句结束后保留并压暗。
- hide：本句结束后退场。
- normal：本句结束后保留正常亮度。

普通 random NPC 的结算顺序已调整为：
提交处方 → 播放治疗成功 / 失败台词与对应立绘 → 显示 JudgementResult → 关闭后切换下一名病人。

6. 数据生产流程
============================================================
主数据源：
- DataTables/Data.xlsx
- DataTables/DetailText/药材
- DataTables/DetailText/疾病
- DataTables/DetailText/方剂
- DataTables/DetailText/说明
- DataTables/DetailText/剧情

主导入脚本：
- DataTables/import_data.py

当前导入顺序：
1. 读取 DetailText 下的正文和剧情分表。
2. 自动备份 Data.xlsx 为 Data.backup_before_detailtext_import.xlsx。
3. 将正文写入对应 sheet。
4. 将 DataTables/DetailText/剧情/*.xlsx 合并写入 StoryLine。
5. 校验 ID、资源路径、枚举值和关联关系。
6. 生成 Data 下的 Godot .tres 资源。

剧情表当前支持：
- StoryID、StoryName
- LineType、Speaker、Text
- PortraitSide、PortraitPath
- BackgroundPath
- Hide：留空 / dim / hide / normal

维护要求：
- Excel 表头命名应逐步统一，避免同一概念出现多种大小写或拼写。
- 每次批量导入后检查 disease.target / formula.recommended 等双向引用。
- 每次批量导入后检查立绘、背景和 Resource 路径是否存在。
- 旧的 backupimport_data.py 已删除；当前只维护 import_data.py。

9. 修改项目时的约束
============================================================
- 不要随意修改 Autoload 名称或 uid。
- 新增数据字段时同步修改 Resource 脚本、import_data.py、Excel 表头和已有 .tres。
- 修改场景节点名时同步检查对应 .gd 的节点绑定。
- 修改 NPC 治疗逻辑时同时检查治疗状态、前后立绘、成功/失败台词、奖励和剧情触发。
- 修改剧情逻辑时同时检查 trigger_type、trigger_scene、trigger_npc_id、clinic_npc_id、return_scene 和存档状态。
- 修改评分逻辑时同时检查 FormulaJudge、JudgeResult、JudgementResult、Clinic 和 Story 诊疗后端。
- 发布或分享工程时保留源资源与 .import 元数据；不要提交 .godot/ 本地缓存。
